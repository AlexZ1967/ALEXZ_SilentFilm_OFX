Проект расположен в `/home/alex/Projects/ALEXZ_SilentFilm_OFX`. Рабочий ComfyUI-пакет SilentFilm не изменяется и используется как справочная реализация. Его Python/PyTorch-инфраструктура в процесс Resolve не встраивается.

## Структура

```text
include/silentfilm/     публичные структуры вычислительного ядра
src/core/              математика без зависимости от OpenFX API
src/ofx/               взаимодействие с хостом
src/cli/               нативный декодер, пересчёт и encoder каденса
scripts/               отдельное окно и внешний Resolve bridge, прежний Lua launcher
tests/                 небольшие независимые тесты ядра
docs/                  план и ручная проверка
```

OpenFX подключается из установленного SDK. Заголовки и Support Library не копируются в проект; SDK-библиотеки и OpenGL не линкуются. Используется C API OpenFX V1, примеры Resolve служат справкой. Для спектральной диффузии используется FFTW3 single precision (`libfftw3f`). Инструкция установки дополнительных зависимостей для Linux и будущей Windows-сборки: [docs/DEPENDENCIES.md](docs/DEPENDENCIES.md). CUDA descriptor включён для Host Probe, Camera, Camera Optics и Projector; в 0.19 добавлены Negative/Print с нормализованным зерном и halation. В 0.20 подготовлен CUDA Defects, его сборки и проверки ещё ожидаются.

## Сборка на текущей Linux-машине

Нужны CMake 3.20+, компилятор C++17, CTest, заголовки OpenFX и FFTW3 single precision. На Debian/Ubuntu установите дополнительную зависимость командой `sudo apt install libfftw3-dev`; полный порядок см. в [инструкции по зависимостям](docs/DEPENDENCIES.md). Команды сборки запускает пользователь:

```bash
cd /home/alex/Projects/ALEXZ_SilentFilm_OFX
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release -DOFX_SDK_ROOT=/opt/resolve/Developer/OpenFX
cmake --build build --parallel 2
ctest --test-dir build --output-on-failure
```

Ожидаемое место результата после успешной сборки:

```text
build/ofx/ALEXZSilentFilm.ofx.bundle/Contents/Linux-x86-64/ALEXZSilentFilm.ofx
```

Для разработки используются системные CMake, CTest и GCC/Clang с поддержкой C++17. Conda и Python для сборки и работы плагина не нужны. Если в терминале активировано Conda environment, перед конфигурацией проекта выйдите из него через `conda deactivate`, чтобы CMake выбрал системный toolchain. Другой SDK задаётся через `OFX_SDK_ROOT`; для стороннего OpenFX SDK можно явно указать `OFX_INCLUDE_DIR`.

CMake содержит расположения бинарников Windows/macOS для дальнейшего развития. Работоспособность на этих ОС пока не заявляется; упаковка, архитектуры и GPU требуют отдельных проверок.

## CUDA-сборка на текущей машине

CUDA включается явно в отдельном каталоге сборки, чтобы сохранить прежний CPU bundle. Для найденного Toolkit `/usr/local/cuda` и установленной NVIDIA RTX 3090 (архитектура 86):

```bash
cmake -S . -B build-cuda -DCMAKE_BUILD_TYPE=Release -DSILENTFILM_ENABLE_CUDA=ON -DCMAKE_CUDA_COMPILER=/usr/local/cuda/bin/nvcc -DCMAKE_CUDA_ARCHITECTURES=86
cmake --build build-cuda --parallel 2
ctest --test-dir build-cuda --output-on-failure
```

Подробности, установка и проверка фактического выбора CUDA в Resolve: [docs/CUDA_VALIDATION.md](docs/CUDA_VALIDATION.md). Эти команды агент не запускал.

Пользователь выполнил CTest 9/9 для 0.10, включая Camera/Projector CUDA parity. Для 0.11 добавлены split Camera и bridge import isolation; CUDA parity дополнен RGB capture. Новые проверки пока не запускались. Прежний emulsion parity не покрывает все пространственные эффекты и расширенный диапазон теней.

Probe и пиксельная сенситометрия используют общую CPU/CUDA-функцию. Camera разделяет маску и расчёт pose между backend, а её CUDA-проходы сравниваются с CPU отдельным тестом. CUDA-путь работает непосредственно с указателями хоста, без копирования всего изображения в RAM и без собственных видеобатчей. Когда Resolve передаёт stream, kernel ставится в него без `cudaDeviceSynchronize` и без ожидания завершения в render. Если stream не передан, ожидается только завершение собственного запуска в default stream. CPU-путь выбирается, когда OFX render передаёт CPU-буферы; ошибки CUDA не маскируются попыткой прочитать GPU-указатель на CPU.

## Установка для проверки в Resolve

Только после успешной сборки и тестов закройте Resolve. Стандартный каталог Linux указан в README установленного SDK: `/usr/OFX/Plugins`.

Если раньше этого bundle ещё не было, скопируйте его вручную:

```bash
sudo mkdir -p /usr/OFX/Plugins
sudo cp -a build/ofx/ALEXZSilentFilm.ofx.bundle /usr/OFX/Plugins/
```

Для последующих замен также закрывайте Resolve. Копируется только собственный bundle, SDK и файлы Resolve не изменяются. После открытия Resolve найдите **SilentFilm Host Probe** в OpenFX/Effects. При необходимости проверьте список разрешённых Video Plugins в настройках Resolve.

Пошаговая ручная проверка: [docs/LINUX_VALIDATION.md](docs/LINUX_VALIDATION.md).

## Параметры прототипа

| Параметр | Действие |
|---|---|
| `Diagnostic Gain (EV)` | 0 — нейтрально, +1 умножает RGB на 2, −1 делит на 2. Альфа не умножается. Это диагностика буфера, без преобразования Log/sRGB и физики плёнки |
| `Temporal Mix` | 0 — текущий кадр, 1 — 50% текущего и по 25% двух соседних. Промежуточные значения плавно включают смешивание. Это проверка temporal access, не optical flow |
| `Neighbor Offset (frames)` | Расстояние до соседей в единицах времени OpenFX (кадры), от 1 до 8; запрос ограничивается диапазоном Source, объявленным хостом |

## SilentFilm Camera

Camera версии 0.6 моделирует ручной каденс 16–20 fps, временную выдержку, связанную с тем же темпом экспозицию, crank-locked сдвиг/наклон и фокус, удерживаемый на виртуальном кадре. Затем применяется монохромная оптика Comfy: переменный Gaussian blur по краям, виньетка, Global Softness и Focus Drift. В 0.7 весь Camera render имеет CUDA-путь и CPU-эталон; backend выбирает Resolve. Временной доступ обязателен. Дискретные исходные кадры получаются однократно на action и интерполируются в ядре; секунды ручки явно переводятся в кадры OFX. Для выдержки используются треугольные веса простого режима Comfy. OFX сохраняет длительность клипа и частоту таймлайна; cadence имитируется удержанием кадров, фильтр не меняет число кадров. Математика и порядок операций перенесены по модели Comfy, но seed/hash последовательность нативная. Версия 0.8 добавляет режим проекции для выраженного изменения скорости движения при неравномерной ручке; timing-тест вошёл в подтверждённый CTest 9/9 версии 0.10. Для физического сокращения длины используйте отдельное приложение, а после него Camera Optics вместо этой Camera.

`SilentFilm Projector` в 0.9 добавляет дрожание позитивной плёнки, мерцание/дыхание лампы и спектральный glow. На GPU используется cuFFT, CPU-эталон — FFTW3. `Glow Strength=0` выключает только светорассеяние; для нейтрального Projector также выключите Gate Weave, Lamp Flicker и Lamp Breathing. `SilentFilm Defects` добавляет детерминированные пыль, царапины, пятна или неоднородность проявки на выбранном этапе. Порядок этапа выбирается в параметре Material Stage.

Пара сохраняет шкалу серого SDR-исходника в пределах точности float32; цветной исходник становится монохромным по линейной яркости Rec.709. Это не HDR/Log-преобразователь и не автоматическое определение рабочего пространства Resolve. Модель ограничивает линейную яркость и позитив диапазоном 0–1. Native view для Gamma 2.4 добавлен явно; Linear/sRGB и кривые плотностей основаны на Python-модели `alexz.neutral_bw_v1`.

Подробные параметры, CST, контроль негатива и сценарий проверки: [docs/NEGATIVE_PRINT.md](docs/NEGATIVE_PRINT.md).

При нулевом gain и mix хост может пропустить render через `IsIdentity`. Если хост не сообщает temporal support, gain остаётся доступным, а попытка включить temporal mix возвращает ошибку поддержки. Молчаливой замены соседних кадров текущим при ошибке доступа нет; на штатной границе диапазона используется крайний кадр.

Для трассировки запросов можно запустить Resolve из своего терминала с переменной `ALEXZ_SILENTFILM_OFX_TRACE=1`. Плагин пишет backend (`CPU` или `CUDA`), время и выбранных соседей в stderr. Не оставляйте трассировку включённой при измерении скорости; при нейтральном эффекте `IsIdentity` может исключить render и строк трассы не будет.

Resolve на текущей Linux-установке перенаправляет stderr в `~/.local/share/DaVinciResolve/logs/ResolveDebug.txt`; отсутствие строк в стартовом терминале не означает отсутствия render.

## Подготовить каденс с изменением длительности

Для целевого кадр-в-кадр используется отдельная команда 0.10, а не OFX-нормировка 0.8. Выберите исходный файл Media Pool, настройте ручку и запустите сгенерированный `build-cuda/scripts/SilentFilm_Cadence.lua`. Нативный `build-cuda/bin/silentfilm_cadence` запечёт Camera в M кадров. При 25 fps новая длительность равна M/25. Далее используется Negative → Print → Projector, повторная Camera не требуется.

Опция `SILENTFILM_BUILD_CADENCE=ON` по умолчанию добавляет helper и требует FFmpeg development libraries; они линкуются только в отдельный процесс, не в OFX/Resolve. Новый Lua/CLI-путь подготовлен для Linux и ждёт пользовательской сборки/проверки. Настройка, зависимости, первый тест 25→20 кадров, ограничения входа/звука/цвета и установка пользовательской команды — [CADENCE_PREPARE.md](docs/CADENCE_PREPARE.md).
