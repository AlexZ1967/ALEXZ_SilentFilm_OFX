## Как пользоваться

1. Собери проект и обнови bundle при закрытом Resolve; команды ниже. Переоткрой Cadence App.
2. В **Processing → Crank Exposure** выбери **Bake Exposure** (заводской режим) или **Exposure via OFX**. Выбор сохраняется в настройках/пресетах; Factory Reset возвращает Bake. Exposure Link задаёт закон ручки в обоих режимах, а не Blend ноды.
3. Рассчитай и импортируй клип обычным способом: заменить выбранный или добавить над ним, без сдвига остального монтажа. В режиме OFX приложение создаёт на результате новую Fusion-композицию **MediaIn → SilentFilm Crank Exposure → MediaOut**, назначает карту именно этого задания, Blend1/Frame Offset0 и проверяет значения обратным чтением. Нода включается только после настройки. Существующие Fusion-графы не заменяются.
4. При сообщении **«настроен в Fusion: карта назначена»** открой страницу **Fusion** на клипе результата и выбери ноду для регулировки Blend. Копировать путь не требуется. Это тот же OFX внутри Fusion, перед Color-цепочкой Camera Optics → Negative → Print → Projector. Нода ожидает sRGB / Rec.709; реальное согласование цвета на границе Fusion/Color требует A/B в твоём проекте. Физический негатив на вход подавать нельзя. Если Fusion API откажет, сообщение явно укажет ручной вариант: выключенный прямой OFX, путь из нижнего поля → Exposure Map, затем включить эффект. Ручную ноду в Color ставь перед Camera Optics/Negative.
5. Blend0 — без колебаний экспозиции, Blend1 — полная сохранённая экспозиция. Регулировка не пересчитывает Cadence. В Bake дополнительную ноду не добавляй.

Файл карты содержит версию, режим bake/ofx, FPS показа, число кадров и индекс/float32 gain каждого кадра. Значения gain соответствуют реально применяемому CPU/CUDA коэффициенту. `capture_map.csv` остаётся диагностической таблицей; новый OFX читает **sfexposure**, а не произвольный CSV. Паспорт результата содержит `exposure_mode`, `exposure_map_path`, `exposure_ofx_id`. Старые задания без exposure_mode считаются Bake.

Карта bake отклоняется нодой с сообщением о повторном применении. Отсутствующая/повреждённая карта, некорректные FPS в самом файле и выход за таблицу также дают диагностику. FPS входного объекта Fusion не используется для выбора gain: OFX time уже задан в кадрах. Ошибка выхода за карту содержит index/count. Blend0 полностью обходит карту, даже если файла нет. **Reload Map** сбрасывает кэш после внешнего восстановления файла. Нода не угадывает карту по последнему заданию, пути исходника или длительности.

Для прямого Resolve `Effect` setter произвольных OFX-параметров по-прежнему не документирован. Автоматика0.27 использует документированные **Fusion Tool.SetInput/GetInput**; реальный registry ID и IDs параметров берутся из GetRegList/GetInputList, не угадываются. Точный OFX ID `blend` имеет приоритет над общим Fusion `Blend`, неоднозначные имена отклоняются. Запись пути проверяется; частичный новый граф удаляется при отказе. Ошибка удаления останавливает дополнительное добавление и требует осмотра результата. Подробности API: [официальное руководство Blackmagic](https://documents.blackmagicdesign.com/UserManuals/Fusion8_Scripting_Guide.pdf), разделы Fusion/Composition/Operator/PlainInput.

Групповая очередь создаёт отдельный граф/карту на каждом результате. Повторный Import уже настроенного задания не дублирует обработку. Для результата0.26 с выключенной нодой нажми Import повторно (в том числе через Open Job): будет попытка настроить существующий монтажный клип, без перерасчёта/повторного импорта медиа. Старый известный выключенный прямой OFX удаляется после успешной Fusion-настройки. Включённые эффекты или неоднозначные дубликаты не перенастраиваются автоматически, чтобы не получить двойную экспозицию. Ошибка записи необязательной диагностики не отменяет успешно настроенную ноду. Диагностика в папке задания: **exposure_binding.json**.

### Кэш и перенос проекта

Храни sfexposure вместе с результатом. В проекте сохраняется путь параметра OFX; при переносе папки переназначь файл. Кэши неизменяемы на экземпляр, активный render сохраняет свой snapshot даже после PurgeCaches. Изображения хоста и stream pointers не кэшируются. Дополнительного VRAM scratch у ноды нет: один kernel/коэффициент на кадр, без flow и повторного capture, CPU fallback.

**Clean Project/Timeline Cache сохраняет задания Exposure via OFX даже при нулевом видимом media usage.** Причина: Resolve API не позволяет надёжно перечислить карты, выбранные в произвольных OFX-параметрах на других копиях клипа. Это консервативная защита файлов; автоматическое удаление неиспользуемых OFX-карт пока не реализовано. Bake/старые задания очищаются по прежним правилам.

## Исходное предложение и обоснование

Native пишет в `capture_map.csv` точный `exposure_gain` каждого выходного кадра вместе с capture FPS/временем экспозиции. Это тот же расчёт ручки, который определяет каденс; новое случайное мерцание не требуется. До0.26 коэффициент всегда запекался при CPU/CUDA render.

Выбор приложения: **Bake Exposure / Exposure via OFX**. В первом режиме остаётся `plan.gain`; во втором render получает gain=1, но исходная карта сохраняется. Каденс, смаз, число кадров и дрожание одинаковы. OFX-режим требует `processing=capture_rgb`; старый full_camera поддерживает Bake. Переход от уже запечённого результата к незапечённому потребует нового расчёта.

Эффект — **SilentFilm Crank Exposure**, перед Camera Optics/Negative. При линейном изменении силы коэффициент равен `1 + Blend * (gain - 1)`; он применяется к линейному RGB с декодированием/кодированием согласно общему sRGB-контракту, SDR clamp0..1 как в исходном bake. Это регулировка линейного gain; при клиппинге она не тождественна выходному lerp двух уже обрезанных RGB. Alpha сохраняется. Режим/проверка карты защищают штатный маршрут от двойного применения, но выбор вручную чужой карты для уже запечённого видео определить по пикселям невозможно.

Карта индексируется выходными кадрами, не кадрами исходника и не абсолютной позицией таймлайна. Перенос клипа не должен менять экспозицию. Подрезка/retiming требуют проверенной индексации времени OFX, при необходимости явного Frame Offset. Каждый результат группового расчёта получает свою карту; нельзя искать глобальное «последнее задание» или угадывать привязку по длительности. Карта хранится с результатом и защищается от очистки используемого кэша. Чтение вне pixel-loop, неизменяемый кэш экземпляра, понятная ошибка отсутствующей карты. Render допускает произвольный порядок кадров и параллельные экземпляры. CUDA — один простой kernel без нового optical flow/temporal sampling; CPU fallback.

В установленной справке Resolve21.1.2 (`/opt/resolve/Developer/Scripting/DaVinciResolveScript.pyi`, CHANGELOG) есть `Resolve.GetEffectsList()` и `TimelineItem.AddEffect('ofx', id)`. У объекта `Effect` есть включение/порядок/информация и `GetFusionComp()` только для Fusion, но нет документированного setter произвольных OFX-параметров. Поэтому0.26 предлагала ручной выбор карты; в0.27 используется отдельная Fusion-композиция с документированными входами инструмента. DRX, заменяющий граф, не используется. Стандартный image ID OFX не является путём клипа.

Следующий шаг — пользовательские тесты и Resolve по инструкции выше. Автоматическое назначение карты подготовлено через Fusion, но реальная работа API, цвет/тайминг и CUDA-путь Fusion ещё не подтверждены runtime. Недокументированные setter для прямого Effect, поиск «последнего job» и подмена существующего grade не использованы.
