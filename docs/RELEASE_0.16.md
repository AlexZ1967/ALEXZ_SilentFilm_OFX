# Итог этапа 0.16 — 2026-11-12

✅ **2026-11-12 — оформлен этап разработки 0.11–0.16.** Текущая версия проекта — 0.16.0. Это сохранение накопленных изменений, а не объявление всех сценариев проверенными.

## Что вошло

- Отдельное GTK 4/Pango приложение Cadence и запуск из меню Scripts в Resolve.
- Работа с выбранным монтажным клипом: его In/Out, прямое получение обработанных кадров через API без Render Queue либо Use Raw Source для чтения исходника без обработок.
- Возврат результата в текущий таймлайн: замена без ripple или добавление над оригиналом. Имена файлов с `_cadence`, резервное восстановление при сбое монтажа.
- Разделение Cadence и Camera Optics: выдержка, движение камеры и экспозиция запекаются в каденсе; виньетка, краевой расфокус и гуляющий фокус остаются в OFX.
- Native CPU/CUDA, передача соотношения сторон пикселя, режим simple и интеграция optical flow с кэшем соседних пар.
- Настройки, именованные пресеты, Factory Reset, папки результатов по проектам/клипам и очистка кэша с проверкой ссылок на медиа.
- Тесты ядра, GPU parity, интеграционного экспорта, bridge, настроек и кэша; инструмент независимого сравнения flow с Comfy.

## Подтверждения и ограничения

Пользователь ранее подтвердил тесты после исправления неподвижной сцены в 0.13.1; полного лога последнего набора нет. В прямом API-экспорте пользователь увидел обработки на пробном кадре. Журналы подтвердили завершённый CUDA-расчёт в новом пути; это не доказывает корректность всех эффектов и цветового тракта.

Последние редакции GUI, пресетов, очистки и удаления служебных backup-таймлайнов требуют пользовательской проверки. Сборки, CTest и Resolve при оформлении этапа агент не запускал.

Артефакты flow на быстром движении пока не объявлены исправленными. Большая разница длительности Comfy/Resolve объяснена разными исходными файлами и числом входных кадров. Нужен A/B на одном файле, одном диапазоне и одинаковых параметрах; точная семантика SourceEndFrame Resolve также требует проверки на границе одного кадра. Windows/macOS не проверены.

## Следующий этап

1. Пользовательская сборка и полный CTest текущего состояния.
2. Проверка подрезки, обоих режимов входа и размещения результата, пресетов и очистки кэша в Resolve.
3. Сравнение flow с Comfy на одинаковых кадрах через `tests/compare_comfy_flow.py`, затем разбор оставшихся артефактов.
