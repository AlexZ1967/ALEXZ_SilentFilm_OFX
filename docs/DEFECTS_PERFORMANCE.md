- **Size Spread (%)** — симметричный разброс размера пыли/пятен вокруг Size, default35. 0 — одинаковый размер, 50 — от0.5 до1.5Size. У царапин отдельный **Thickness Spread (%)**, также0..100/default35.

## Исправление видимого хода Blend/Strength — 0.22

✅ **2026-11-12 — пользователь подтвердил проблемный случай: Material Stage=Negative, просмотр после Print.** Найдено смешивание в неправильном для ожидаемой непрозрачности пространстве: прежде интерполировалось физическое пропускание T негатива. Его изменение Print нелинейно переводит в позитив. Например, на белом участке T≈0.002, а прозрачная основа царапины≈0.794. Даже примесь0.001 поднимает T примерно до0.00279 и снижает видимый sRGB-уровень примерно с1 до0.8; примесь0.5 уже выглядит почти чёрной. Это объясняет ощущение «полоса сразу включилась», несмотря на линейный lerp самого T.

В 0.22 **Blend первым** объявлен в descriptor и первым поставлен в Controls, выше Material/Pattern/Strength. Следом новый **Mix Response**:

- **Perceptual — smooth fades** (default). Strength регулирует непрозрачность полного рисунка, Blend регулирует наложение всей ноды. Итоговая непрозрачность — `Strength × Blend`, без изменения seed/геометрии. Для Capture/Positive/Projector смешивается видимый выходной RGB. Для Negative/Printing исходник и полный эффект переводятся в фиксированный нейтральный позитив sRGB, смешиваются там и возвращаются обратно в физическое пропускание. Print продолжает получать негатив, а не закодированный позитив. При Strength=1 Blend0.5 даёт половину видимого эффекта после нейтрального Print; при Strength0.5 Blend0.5 — четверть. 0 остаётся точным bypass, 1×1 сохраняет прежний полный эффект.
- **Physical material** сохраняет прежнюю силу маски/плотности и lerp физического материала. Нелинейный ход после Print в этом режиме ожидаем. Выбирай его для сравнения физической математики Comfy; полная Comfy-эквивалентность Defects от этого не появляется.

Все mapped-пресеты выбирают Perceptual, Blend1. Если нужна старая картинка с промежуточным Strength, переключи Mix Response в Physical. В Perceptual изменилось назначение Strength также у Development: это непрозрачность готового поля; Physical сохраняет прежнее масштабирование плотности. Физический режим не удалён и не выдаётся за программную ошибку сам по себе — он не соответствовал ожидаемому пользователем плавному видимому миксу.

Калибровка Perceptual для негатива соответствует **нейтральному Print, sRGB**, как в заданном workflow. Другая экспозиция/контраст/toe/shoulder/transfer Print или последующие нелинейные эффекты могут изменить видимый ход; OFX Defects не знает параметры последующих нод. При просмотре самого физического негатива линейность RGB не обещается: эта опция предназначена для просмотра после Print. Для остальных стадий это обычное смешивание выхода ноды. Alpha/premultiply поддерживаются, используются общие CPU/CUDA-функции, кадровых буферов не добавлено; дополнительная калибровка выполняется только там, где есть эффект и неполная непрозрачность.

Новые регрессии проверяют **реальную цепочку Negative → Defects Scratches → Print** при Strength0.001/0.1/0.5/1 и Blend0/0.001/0.5/1, разные уровни серого/alpha representation, также Printing. Отдельно воспроизводится сильное усиление старого Physical0.001. Общий parity включает оба режима; физическая регрессия сохраняет допуск2e-6. Для perceptual негативного пропускания допускается4e-5, но дополнительно контролируется видимый результат реального Print ≤8e-5: обратная калибровка чувствительна к float-погрешности возле чёрного. Сам линейный видимый ход нейтральной цепочки проверяется с допуском4e-5. **Сборки, тесты и Resolve агент не запускал; исправление пока не имеет пользовательского PASS.**

После сборки/CTest и обновления bundle проверь на нейтральном Print из workflow: Material=Negative, Pattern=Scratches, Mix Response=Perceptual. Сначала Strength=1 и Blend0/0.001/0.25/0.5/1; затем Blend=1 и те же значения Strength. Не включай две регулировки0.5 одновременно, если проверяешь именно половину эффекта. ## История 0.20–0.21

✅ **2026-11-12 — подготовлен общий Blend, версия 0.21.** Ползунок **Blend** (0–1, по умолчанию 1) смешивает исходный кадр с готовым результатом Defects после всех преобразований: `out = source × (1 − Blend) + effect × Blend`. Смешивание выполняется в выходном представлении сигнала ноды, с согласованным premultiply; alpha остаётся исходной. Это отдельная регулировка от Strength, который меняет саму маску/плотность. Blend анимируется обычными OFX-ключами. При 0 эффект полностью bypass, включая Development; при 1 сохраняется прежний полный результат. Все reference-пресеты Defects устанавливают Blend=1 для чистого сравнения. CPU и CUDA используют один общий pixel-код без промежуточного изображения. Регрессии дополнены значениями 0/0.37/1 и независимым смешиванием source + старого renderer. Новые проверки агент не запускал; PASS0.20/0.21 пока не подтверждён.

✅ **2026-11-12 — подготовлен CUDA-путь и оптимизация CPU.** Пользователь подтвердил работу предыдущей 0.19, но сообщил, что dirt очень медленные. Сборки, тесты и Resolve этой редакции агент не запускал; ускорение в цифрах не измерено.

## Причина и изменения

В 0.19 Defects объявляли только CPU. Несколько dirt-нод в цепочке между CUDA-эмульсиями и проектором требовали CPU-обработки; фактическое число переносов буферов определяет Resolve. Внутри CPU-цикла для каждого пикселя повторно считались одни и те же hash-координаты, размеры, вероятность дробной части amount и наклон каждой частицы. Кроме того, весь кодированный кадр проходил decode/encode даже там, где маска дефекта была строго нулевой.

В 0.20:

- Геометрия до 64 частиц и параметры события считаются **один раз на кадр**, без сохранения указателей изображений и без зависимости от порядка запросов.
- Dust/Scratches сначала отвергают пиксели вне конечной области воздействия; для фона пропускаются sqrt и цветовые преобразования. У Stains бесконечные Gaussian-хвосты не обрезаются.
- Нулевая маска копирует исходный пиксель с нужным представлением alpha. Монохромный кадр проходит одну transfer-пару вместо трёх. Формы, плотностная модель, seed и дробный amount сохранены в пределах float-точности.
- `strength=0`, а для частиц также `amount=0`, сообщаются хосту через OFX IsIdentity. Хост может пропустить render целиком. Development не отключается через amount, поскольку этот параметр в данной ветке не используется.
- **Все четыре native pattern** (Dust, Scratches, Stains, Development) имеют CUDA-реализацию: один kernel по переданному GPU-изображению, без промежуточных масок, malloc кадрового scratch, копирования в RAM и FFT. Маленький пакет геометрии передаётся аргументом kernel. Используется host stream; при его отсутствии ожидается собственный запуск в default stream.

Если хост передаёт CPU-буферы, используется оптимизированный CPU-код. Нельзя пытаться обработать GPU-указатель на CPU при ошибке CUDA; ошибка возвращается хосту. Выбор GPU определяется OFX render, а не отдельной пользовательской галочкой.

## Исправление времени

Обнаружена отдельная ошибка адаптера: OFX `time` уже измерялся в кадрах, но прежний Defects core трактовал его как секунды и повторно умножал на FPS. Теперь adapter передаёт `(time − SourceStart) / FPS`, а core определяет физический индекс кадра с небольшим допуском для double-округления.

**Persistence=48 теперь означает 48 кадров**, около 1.92 с на таймлайне 25 fps. При возвращении к кадру seed/рисунок воспроизводится. По сравнению с прежним неверным ходом времени смена событий станет медленнее; это исправление единиц времени, а не снижение детализации. Старые проекты могут показать другое расписание событий на тех же абсолютных OFX time.

Это ускорение существующей native модели. Полная математическая эквивалентность отдельным Comfy damage_type/когерентным полям/edge bias всё ещё не реализована; `mapped`-пресеты сохраняют прежний смысл. Подробности — [COMFY_WORKFLOW_MATCH.md](COMFY_WORKFLOW_MATCH.md).
