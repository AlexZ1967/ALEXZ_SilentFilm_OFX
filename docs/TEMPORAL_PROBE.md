# TemporalProbe — проверка доступа к кадрам за монтажным концом

## Команда «Уместить исходник»

Команда запускается из меню Resolve после правой подрезки. Она считывает полную длину исходника и монтажную длину выбранного клипа, вычисляет скорость `полная длина / монтажная длина × 100%` и применяет её через встроенный ретайм. Например, 200 кадров в слоте из 100 кадров дают 200%. В конце команда проверяет начало и конец клипа на таймлайне и достижение исходного конца. При расхождении она пытается вернуть прежние значения и сообщает результат в консоли.

При закрытом Resolve установите скрипт:

```bash
mkdir -p ~/.local/share/DaVinciResolve/Fusion/Scripts/Utility
cp "scripts/Уместить исходник.py" ~/.local/share/DaVinciResolve/Fusion/Scripts/Utility/
```

1. На странице **Edit** возьмите обычный отдельный видеоклип без связанных дорожек. FPS файла и таймлайна должны совпадать, начальная скорость — 100%. Для визуальной проверки удобно взять клип с номерами внутри кадра.
2. Подрежьте клип справа, выделите его и выберите **Workspace → Scripts → Utility → Уместить исходник**. Если на тестовом клипе уже есть диагностический эффект Temporal Probe, отключите его для проверки встроенного ретайма.
3. Сверьте правый край на таймлайне и изображение в конце. Консоль Resolve показывает исходную и итоговую длину, фактическую скорость либо причину отказа. Последний показанный кадр зависит от выборки встроенного ретайма. Проверьте его на исходнике с номерами до применения команды к рабочим клипам.

Команда использует `TimelineItem.SetSpeed` и `SetRightOffset` из установленного Resolve 21.1+. Её можно установить отдельно от диагностического OFX. Выполнение в Resolve ещё не подтверждено.

## Диагностический OFX

Отдельный диагностический OFX bundle, plugin ID `com.alexz.silentfilm.temporalprobe`. Прототип не является публичным контрактом SilentFilm и не меняет длительность таймлайна.

## Сборка

Пользователь собирает только цель диагностического плагина системными CMake и C++17:

```bash
cmake -S . -B build -DSILENTFILM_BUILD_CADENCE=OFF -DSILENTFILM_ENABLE_CUDA=OFF
cmake --build build --target TemporalProbe -j
```

Bundle появится в `build/ofx/TemporalProbe.ofx.bundle`. Стандартный каталог установки на Linux — `/usr/OFX/Plugins`, там уже установлен основной SilentFilm. Закройте Resolve и скопируйте весь bundle:

```bash
sudo cp -a build/ofx/TemporalProbe.ofx.bundle /usr/OFX/Plugins/
```

Для разового запуска без копирования можно передать Resolve переменную `OFX_PLUGIN_PATH`. Укажите родительский каталог, в котором лежит bundle. Поддержку этого способа в установленной версии Resolve ещё не проверяли:

```bash
OFX_PLUGIN_PATH="$PWD/build/ofx${OFX_PLUGIN_PATH:+:$OFX_PLUGIN_PATH}" /opt/resolve/bin/resolve
```

## Проверка ускоренным воспроизведением

### Ручная настройка по трём кадрам

Выключите **Auto Timing** и укажите номера в одной системе отсчёта OFX:

| Поле | Какой кадр указать | Пример |
| --- | --- | ---: |
| **Start Frame (OFX)** | Первый кадр после подрезки справа | 0 |
| **Trimmed Frame (Last)** | Последний видимый кадр подрезанного клипа | 99 |
| **Full Source Frame (Last)** | Последний кадр исходника до подрезки | 199 |

В этом примере выходной диапазон `0…99` показывает исходный диапазон `0…199`. В версии 1.5 крайние кадры включены. Для прохода с цветовой диагностикой задайте **Trimmed Frame (Last)** равным **Start Frame (OFX)** и читайте `time=` из строк `mode=probe`. Настройки длины из 1.4 не переносятся на поля с номерами кадров.

### Автоматический расчёт через скрипт

В вашей конфигурации Resolve сообщил OFX одинаковый диапазон Source и Output. Для определения подрезки используйте скрипт из версии 1.4. При закрытом Resolve установите его рядом с другими пользовательскими скриптами:

```bash
mkdir -p ~/.local/share/DaVinciResolve/Fusion/Scripts/Utility
cp "scripts/Temporal Probe Timing.py" ~/.local/share/DaVinciResolve/Fusion/Scripts/Utility/
```

1. На странице **Edit** подрежьте клип справа и выделите его. Для этого прогона исходник должен начинаться с первого кадра файла, идти со скоростью 100% и иметь тот же FPS, что и таймлайн.
2. Запустите **Workspace → Scripts → Utility → Temporal Probe Timing**. Скрипт прочитает **Frames** из Media Pool и **GetDuration** у выбранного клипа. Путь к файлу он напечатает в консоли Resolve. Файл также можно найти в `~/.local/share/ALEXZSilentFilm/TemporalProbe/`.
3. На **Color** откройте настройки **Temporal Probe**, оставьте **Auto Timing** включённым и выберите созданный файл в **Timeline Timing File**. Привязка файла нужна один раз после каждого изменения подрезки. Длины вручную вводить не нужно.
4. На последнем кадре подрезанного клипа сравните изображение с оригинальным концом файла. В логе `/tmp/TemporalProbe.log` ищите `timing=resolve-script`, `start=`, `trimmed_end=`, `source_end=` и `request=`. Например, при начале с 0 и длинах 200 → 100 последняя строка должна показать `time=99 request=199`. `readable=1` означает получение изображения. Совпадение с оригинальным последним кадром подтверждает, что Resolve отдал нужный кадр.

### Проверка только через OFX

Вариант без файла полезен для диагностики других конфигураций Resolve, в которых OFX сообщает раздельные границы:

1. Возьмите клип с движением или номерами кадров, записанными прямо в видео. Используйте тот же FPS, что на таймлайне, скорость 100% и подрезайте только справа.
2. Добавьте **Temporal Probe** на ноду Color. Оставьте **Auto Timing** включённым и **Timeline Timing File** пустым. Плагин берёт границы Source и Output и учитывает длительность эффекта, если Resolve её сообщает. Если Source и Output начинают отсчёт в одной точке и удалось выделить более короткий выходной отрезок, плагин распределит заявленный исходный диапазон по выходу.
3. На последнем кадре сравните картинку с оригинальным концом файла. Если виден исходный последний кадр, Resolve отдал кадр за подрезкой. Если движение замерло на прежнем монтажном кадре, хотя `request=` в строках `mode=stretch` увеличивается, Resolve, вероятно, повторяет край.
4. Если экран красный, посмотрите последнюю строку `mode=stretch`. `ready=0` означает, что по данным OFX не удалось выделить две границы. В этом случае поле `request` не использовано. `ready=1 readable=0` означает, что рассчитанный запрос не дал читаемый кадр. `source=1[…]`, `output=1[…]` и `duration=1:…` обозначают успешно прочитанные значения свойств хоста. Даже при `ready=1` исходный последний кадр следует сверить с оригиналом.

## Проверка по отпечаткам

1. Возьмите клип с заметным движением по всему кадру. Используйте одинаковый FPS у клипа и таймлайна, скорость 100% и пустой участок после клипа. Укоротите правый край на 70 кадров или больше.
2. На странице Color добавьте **Temporal Probe**, выключите **Auto Timing**, задайте **Trimmed Frame (Last)** равным **Start Frame (OFX)** и поставьте курсор на последний видимый кадр клипа. Запишите строку `mode=probe` для этого кадра из `/tmp/TemporalProbe.log`. В ней есть окно источника, которое сообщает Resolve, и время, статус и хеш для каждого запроса. Хеш `-` означает, что отпечаток получить не удалось.
3. Удлините тот же клип вправо. Перейдите на 10, затем на 60 кадров правее прежнего последнего кадра. Сверьте время `current@` в этих строках со временем `current+10@` и `current+60@` из строки до удлинения. Сохраните одинаковые настройки просмотра и масштаб. Если Resolve использовал кэш рендера и новых строк нет, выключите кэш рендера для прогона.
4. Сравните хеши. Совпадение запроса из обрезанного клипа с контрольным `current` того же кадра после удлинения, при отличии от прежнего последнего кадра, подтверждает доступ к ожидаемому кадру за монтажным концом. Совпадение с прежним последним кадром при отличающемся контрольном хеше указывает на повтор края. `fail` при успешном `current` означает, что данный запрос не вернул изображения. При пустом хеше, одинаковых контрольных кадрах или несовпадении координат одного цвета для вывода недостаточно.

`max` — конец диапазона, который объявляет Resolve. Он может отличаться от монтажного конца. Зелёный означает, что хотя бы один запрос `max+10` или `max+60` вернул изображение. Красный означает отказ обоих запросов. Для проверки монтажного конца используйте `current+10` и `current+60` с курсором на последнем видимом кадре. Все смещения заданы в кадрах OFX.

Для просмотра свежих строк используйте `tail -n 15 /tmp/TemporalProbe.log`. Если после обновления плагин снова пропадёт из списка, закройте Resolve и переименуйте `~/.local/share/DaVinciResolve/configs/OFXPluginCacheV2.xml`, чтобы Resolve пересоздал кэш при запуске.
