# Память и завершение OFX — 0.25

✅ **2026-11-12 — выполнен аудит кода и подготовлены исправления. Сборки, тесты, профилирование и Resolve агент не запускал.** Пользователь сообщил долгий выход и сообщение о некорректном завершении; уточнил: Glow в Projector включён, Halation Strength в Negative/Print равен0. Это указывает на актуальность FFT-пути Projector, но не доказывает причину конкретного завершения.

## Найдено и изменено

1. `ProjectorCudaCache` сохранял по четыре cuFFT-плана для каждой новой комбинации CUDA context/stream/размера без лимита. Это удержание кэшируемых ресурсов до удаления экземпляра, а не доказанная потеря всех указателей. Теперь максимум **8 наборов на экземпляр**. При обращении обновляется LRU; при вытеснении сначала выбирается завершённый набор текущего контекста. Если все заняты, освобождение старого набора может ждать его событие. Лимит не является общим бюджетом VRAM всех нод.
2. Деструктор каждого такого кэша создавал `std::thread` и сразу делал `join()`. Очистка зависела от создания/запуска дополнительного потока во время выхода; исключение создания потока оставляло driver-ресурсы до уничтожения контекста. Убран этот поток. Очистка выполняется непосредственно: временный `cuCtxPushCurrent` владельца → ожидание собственного события → уничтожение собственных планов/события → `cuCtxPopCurrent`, восстанавливающий прежний контекст потока. CUDA-контексты и streams Resolve не уничтожаются. Дедлок прежнего варианта на машине пользователя не воспроизводился агентом и не объявляется доказанным.
3. Проверка `if (cufftHandle)` заменена отдельным флагом успешного создания для каждого плана: числовой0 не используется как признак отсутствия ресурса. Частично созданные наборы тоже очищаются.
4. Ошибки удаления планов, событий и временных буферов теперь диагностируются. Неосвобождённые при ошибке наборы сохраняются для повторной попытки purge, если экземпляр продолжает жить. При уже уничтоженном хостом CUDA context очистить его ресурсы через этот context невозможно; ошибка явно выводится вместо молчаливого пропуска.
5. OFX теперь обрабатывает `kOfxActionPurgeCaches`: освобождает CPU-кэши ручки/фокуса/проектора и GPU FFT-кэш. При следующем обращении всё строится заново детерминированно. У CPU-векторов освобождается и capacity. Кэш не сбрасывается автоматически после каждого кадра/EndSequenceRender, чтобы не пересоздавать FFT при каждом коротком интерактивном render. Вызов purge зависит от хоста.
6. На успешном пути Projector временный VRAM-буфер ставится на освобождение **до** события завершения. В spatial Negative/Print освобождение также ставится до проверки синхронного завершения без host stream; ошибки `cudaFreeAsync` больше не скрываются в деструкторе. На исключениях остаётся RAII cleanup.

## Что проверено чтением кода

- Host images освобождаются `Image` при выходе из action, в том числе после ошибки чтения свойств; их указатели не хранятся в instance cache.
- Instance удаляется через `DestroyInstance`. Долгоживущих глобальных image/GPU caches и рабочих потоков в OFX нет; кэш планов принадлежит экземпляру, а не всему Resolve.
- CPU пространственные буферы — локальные vector/unique_ptr. FFTW-планы и alloc-буферы имеют deleters; planner/destruction сериализованы mutex. Явной утечки обычного пути чтением кода не выявлено; это не результат измерения утечек.
- Camera GPU имеет парный cudaMallocAsync/cudaFreeAsync, Defects вообще не выделяет кадрового GPU scratch. Пространственные эмульсии используют RAII.
- Не добавлены `cudaDeviceReset`, глобальный `fftwf_cleanup` или уничтожение host streams: они могли бы затронуть ресурсы Resolve/других плагинов. Объём VRAM, удержанный runtime/pool, сам по себе не доказывает потерянное выделение нашего плагина.

Контракт контекстов сверялся с [NVIDIA CUDA Driver API](https://docs.nvidia.com/cuda/archive/13.0.0/cuda-driver-api/group__CUDA__CTX.html), владение ресурсами планов — с [cuFFT13](https://docs.nvidia.com/cuda/archive/13.0.0/cufft/index.html#cufftdestroy). OFX stream/purge — установленный `ofxGPURender.h`/`ofxCore.h`: работа в host stream остаётся асинхронной; device-wide synchronize не добавлен.

## Проверки пользователя

```bash
cd /home/alex/Projects/ALEXZ_SilentFilm_OFX
cmake --build build-cuda --parallel 2 &&
ctest --test-dir build-cuda --output-on-failure
```

Расширен существующий `silentfilm_projector_cuda_parity`: заполнение/вытеснение кэша, предел8, purge/rebuild/повторный purge, вызов без текущего CUDA context и восстановление context, очистка после уничтожения host stream, деструктор с незавершённой работой. CPU tests проверяют неизменность фокуса/ручки/лампы после purge. Пиксельные CPU/CUDA parity сохранены. **Результатов запуска этой редакции пока нет.**

При установленном NVIDIA Compute Sanitizer дополнительная проверка утечек/доступов отдельного теста:

```bash
/usr/local/cuda/bin/compute-sanitizer --tool memcheck --leak-check full --error-exitcode 1 ./build-cuda/silentfilm_projector_cuda_tests
```

После успешной сборки, при закрытом Resolve, пользователь обновляет bundle:

```bash
sudo cp -a build-cuda/ofx/ALEXZSilentFilm.ofx.bundle /usr/OFX/Plugins/
```

Затем повторить прежний проект: Glow включён, просмотр/перемотка, закрытие. Для сравнения повторить с Glow0. Если выход остаётся медленным/аварийным, запустить Resolve с логом из корня проекта:

```bash
mkdir -p renders
ALEXZ_SILENTFILM_OFX_TRACE=1 /opt/resolve/bin/resolve > renders/resolve_shutdown.log 2>&1
```

Лог содержит begin/end actions, begin/end cuFFT cleanup, число наборов/оставшихся, код и время. Медленные очистки от250ms/ошибки печатаются и без TRACE. Последний begin без end помогает локализовать остановку, но сам по себе не доказывает причину crash. Агент Resolve не запускал; подтверждение устранения симптома остаётся следующим шагом.
