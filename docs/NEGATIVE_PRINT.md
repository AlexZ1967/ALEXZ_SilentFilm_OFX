# Negative → Print: первая реализация плёночной пары

## Статус и границы

В исходниках bundle 0.3 появились два самостоятельных OpenFX-эффекта:

- **SilentFilm Negative**, ID `com.alexz.silentfilm.negative`.
- **SilentFilm Print**, ID `com.alexz.silentfilm.print`.

Используются общие математические функции CPU/CUDA. Host Probe остаётся отдельным эффектом с прежним ID. Пользователь подтвердил, что все тесты версии 0.3 прошли и Negative → Print правильно работает в Resolve. В исходниках версии 0.4 добавлено зерно эмульсии для Negative и Print; новый код ждёт пользовательской сборки и проверки. Полный лог прогона 0.3 и состав ручной проверки не предоставлены; отдельное подтверждение экспорта, отмены, alpha и Fusion не зафиксировано.

В версии 0.3 перенесена тональная часть Python-модели `alexz.neutral_bw_v1`: экспозиция, проявка, toe/shoulder, вуаль и печать через реальное пропускание негатива. В версии 0.4 добавлено многомасштабное зерно плотности с фиксированным алгоритмом v1. Halation, пространственная оптика и временные изменения пока не входят.

## Физическое представление

Negative декодирует выбранный SDR-сигнал, переводит его в линейную монохромную яркость Rec.709, вычисляет экспозицию и плотность, затем выдаёт пропускание плёнки `T = 10^-D`. Альфа сохранена с учётом представления, которое сообщил хост.

Print принимает именно пропускание плёнки. Оно не декодируется повторно как sRGB/Log. Вычисляется экспонирование позитивного материала через негатив и его проявка. После этого применяется фиксированная калибровка просмотра и выбранное выходное кодирование. Автоконтраста, нормализации по гистограмме и скрытой копии исходного изображения нет.

При нейтральной паре шкала серого возвращается к исходной в пределах точности float32. Цветной исходник становится чёрно-белым: сохранения исходного цвета эта пара не обещает. Изменения Negative действительно проходят через Print; Print не отменяет автоматически художественные настройки Negative.

## Цветовой контракт

| Encoding | Что передаётся на вход Negative / получается на выходе Print |
|---|---|
| `Linear Rec.709` | Линейный свет с первичными Rec.709; значение по умолчанию |
| `sRGB` | sRGB-кривая с первичными Rec.709; соответствует варианту sRGB Python-модели |
| `Rec.709 Gamma 2.4` | Явная степенная кривая 2.4 с первичными Rec.709; не OETF BT.709 |

Выбирайте одинаковое `Input Encoding` Negative и `Output Encoding` Print для нейтральной проверки. Эти настройки не связаны автоматически: отдельного `film_json` в OFX-графе нет.

**Первую проверку проводите на SDR-материале с известным кодированием, без дополнительных коррекций между эффектами.** Для Log, DaVinci Wide Gamut/Intermediate, ACES или другого рабочего пространства нужны явные преобразования до и после пары. Не выбирайте sRGB только потому, что материал выглядит обычным SDR во viewer.

Пример контролируемого варианта в Color:

```text
CST: ваше рабочее пространство → Rec.709 / Linear
  → SilentFilm Negative: Input Encoding = Linear Rec.709
  → SilentFilm Print: Output Encoding = Linear Rec.709
  → CST: Rec.709 / Linear → ваше рабочее пространство
```

Для математического сравнения CST не должен добавлять отдельный tone mapping или gamut mapping. Просмотр и выходные преобразования проекта также должны быть одинаковы при сравнении bypass/обработки. Если материал уже SDR Rec.709 Gamma 2.4 в обычном DaVinci YRGB-процессе, можно явно выбрать Gamma 2.4 в обоих эффектах без этих CST.

Модель ограничивает линейную яркость на входе негативного материала диапазоном 0–1, а отображаемый позитив — диапазоном 0–1. Это намеренно ограниченный SDR-этап, не обещание сохранить HDR и out-of-gamut данные. Технические детали чёрного ограничены float32-представлением физического пропускания; битовая тождественность исходнику не заявляется.

Не вставляйте CST, LUT или цветокоррекцию **между** Negative и Print при нейтральной проверке: между ними находятся данные плёнки, а не обычный цветной сигнал. Когда появятся отдельные дефекты негатива, они будут работать в этом физическом представлении.

## Параметры Negative

| Параметр | Смысл и старт |
|---|---|
| `Negative Exposure (EV)` | 0 — нейтральная экспозиция негатива. Плюс увеличивает плотность негатива и осветляет итоговый позитив, минус затемняет позитив. Начните с 0 и меняйте по 0.1–0.25 |
| `Development Contrast` | 1 — нейтральная проявка. Меньше 1 мягче, больше 1 контрастнее; поворот около 18% линейного серого. Для начала 1 |
| `Shadow Compression` | Компрессия теневого участка сцены, 0 — выключена. Для нейтральной пары оставьте 0 |
| `Highlight Compression` | Компрессия светового участка сцены, 0 — выключена. Для нейтральной пары оставьте 0 |
| `Base Fog` | Дополнительная плотность материала; 0 — нет вуали. Это не простая непрозрачная плашка поверх изображения |
| `Input Encoding` | Явное кодирование изображения до съёмки; первичные — Rec.709 |
| `View Positive (preview only)` | Показывает полученный негатив через фиксированную нейтральную печать. Это меняет выход эффекта: перед подключением Print выключите этот флаг |
| `Emulsion Grain` | Сила структурированного зерна в плотности негатива; 0 — выключено. Для первого просмотра начните с 0.02–0.04 |
| `Grain Size` | Размер фактуры относительно ширины кадра 1920 px; старт 2. Меняется вместе с разрешением/proxy |
| `Grain Seed` | Целочисленный seed фактуры. Повторный render того же времени и координат даёт тот же рисунок |

Сам по себе негатив может выглядеть очень тёмным и необычно контрастным во viewer: он представлен физическим пропусканием, а не нормализованной инверсией для просмотра. Для настройки отдельно от Print включите `View Positive`; если Print уже подключён, временно bypass Print, иначе он примет этот позитив за негатив и результат будет неверным.

## Параметры Print

| Параметр | Смысл и старт |
|---|---|
| `Print Exposure (EV)` | Свет при печати. 0 — нейтрально; плюс повышает плотность позитивной плёнки и **затемняет** результат, минус осветляет. Направление отличается от Negative Exposure |
| `Print Contrast` | 1 — нейтральная печать. Меньше 1 мягче, больше 1 контрастнее; около калиброванного среднего серого |
| `Shadow Compression` | Компрессия теней позитивного изображения, 0 — выключена |
| `Highlight Compression` | Компрессия светов позитивного изображения, 0 — выключена |
| `Base Fog` | Дополнительная плотность позитивного материала, 0 — выключена |
| `Output Encoding` | Кодирование отображаемого позитива; для нейтрального сравнения совпадает с Input Encoding Negative |
| `Emulsion Grain` | Сила структурированного зерна позитивной эмульсии в оптической плотности; 0 — выключено. Зерно негатива уже проходит через печать, поэтому начинайте с 0–0.015 |
| `Grain Size` | Размер фактуры относительно ширины кадра 1920 px; общий смысл тот же, что у Negative |
| `Grain Seed` | Seed позитивной эмульсии; внутренний поток Print отделён от потока Negative |

В обоих этапах сохраняется alpha; premultiplied RGB разворачивается до нелинейной математики и формируется заново в представлении output image хоста. Альфа не используется для передачи состояния или индекса плёнки.

## Нейтральная настройка

1. Negative: exposure=0, contrast=1, обе compression=0, fog=0, `View Positive=off`.
2. Print: exposure=0, contrast=1, обе compression=0, fog=0.
3. Encoding одинаковый и соответствует действительному сигналу между вашими цветопреобразованиями.
4. Сначала сравните серую шкалу и уже монохромный исходник; цветной исходник сравнивайте с его линейным Rec.709-монохромным вариантом.

Для первой художественной настройки начинайте с Negative Exposure. Затем немного уменьшайте Development Contrast, например до 0.9, если нужно мягче. Не включайте компрессию обоих материалов сразу: сначала оцените один этап, затем другой. Полное совпадение деталей и контраста проверяется при нейтральных значениях, а не при дополнительной компрессии.

## Сборка и автоматические проверки пользователем

Для уже настроенного CUDA build из предыдущего этапа:

```bash
cd /home/alex/Projects/ALEXZ_SilentFilm_OFX
cmake --build build-cuda --parallel 2
ctest --test-dir build-cuda --output-on-failure
```

CMake автоматически перечитает изменённый проект. Ожидаются три теста: core, sensitometry и CUDA parity. Серая шкала проверяется в линейном свете и кодированных значениях; плотности — относительно отдельного double-эталона. GPU-сравнение включает оба материала, preview, transfer, alpha, границы и stride. Вблизи чёрного допустимое отклонение в кодированном значении шире из-за float32-пропускания, дополнительно проверяется малая ошибка в линейном свете.

При желании проверить CPU-only сборку отдельно:

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release -DSILENTFILM_ENABLE_CUDA=OFF
cmake --build build --parallel 2
ctest --test-dir build --output-on-failure
```

Здесь ожидаются два теста; CUDA не требуется. Агент ни одну из этих команд не запускал.

## Проверка в Resolve после успешной сборки

Полностью закройте Resolve, затем замените только собственный bundle:

```bash
sudo cp -a build-cuda/ofx/ALEXZSilentFilm.ofx.bundle /usr/OFX/Plugins/
```

1. Найдите в Effects `SilentFilm Negative` и `SilentFilm Print`. Host Probe должен остаться доступным.
2. Создайте две последовательные ноды без другой обработки между ними и примените Negative → Print.
3. С нейтральными настройками сравните обработку с bypass обоих эффектов на монохромной шкале/кадре.
4. Bypass Print, включите `View Positive` у Negative. Он должен показать результат фиксированной нейтральной печати; затем выключите preview и снова включите Print.
5. Проверьте направления EV: плюс у Negative осветляет позитив, плюс у Print затемняет.
6. Проверьте alpha на RGBA-материале, короткий экспорт и отмену. Повторите в Fusion, если планируете этот контекст.
7. Для подтверждения backend смотрите трассу в `~/.local/share/DaVinciResolve/logs/ResolveDebug.txt`. Теперь строка содержит также `effect=SilentFilm Negative` или `effect=SilentFilm Print`.
8. Для проверки зерна сначала оставьте `Emulsion Grain=0` и убедитесь, что пара сохраняет прежний результат. Затем задайте небольшую силу у Negative, проверьте одинаковый рисунок после повторного render и перемотки к тому же кадру; попробуйте другой seed. Отдельно задайте слабое зерно Print. Проверка зерна на GPU пока не входит в существующий CUDA parity тест.

Пользователь подтвердил, что Negative → Print работает правильно в Resolve. Перечисленные выше отдельные проверки (alpha, экспорт, отмена, Fusion и backend trace) не следует считать подтверждёнными без дополнительных результатов.
