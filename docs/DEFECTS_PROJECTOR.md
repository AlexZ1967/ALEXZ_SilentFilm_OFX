# Projector и самостоятельные дефекты

## Состояние версии 0.9

Добавлены два отдельных OpenFX-эффекта: **SilentFilm Projector** (`com.alexz.silentfilm.projector`) и **SilentFilm Defects** (`com.alexz.silentfilm.defects`). Это новые прототипные интерфейсы; параметры и IDs пока не являются финальным публичным контрактом. Новая версия не собиралась и не проверялась агентом.

## Projector

Projector принимает готовый позитив, декодирует выбранный Linear/sRGB/Gamma 2.4 transfer в линейный свет, вычисляет раздельную для RGB spectral diffusion-копию и смешивает её с исходником по `Glow Strength`. `Glow Size` — sigma в процентах ширины. Ядро Comfy:

```text
blurred = diffuse_x(diffuse_y(linear_rgb, sigma), sigma)
output  = linear_rgb * (1 - strength) + blurred * strength
```

По каждой оси данные отражаются с повторением крайнего значения; спектральный отклик — `exp(-2 * (sigma * sin(pi * frequency))^2)`. Нулевая сила выключает размытие и FFT. Альфа сохраняется и исключена из светорассеяния. Спектральные преобразования выполняются FFTW3 single precision (`libfftw3f`).

В 0.9 добавлены дрожание транспорта плёнки и лампа, а весь Projector перенесён на CUDA, включая спектральный glow через cuFFT. CPU-эталон использует FFTW3; CUDA-путь работает с images хоста в его stream, без пиксельного readback/upload. Оба варианта сохраняют SDR-контракт 0–1 и одинаковый порядок: **gate weave → decode → lamp gain → glow → clamp → encode**. Изображение и alpha сдвигаются вместе bilinear border sampling; premultiplied RGB распрямляется до интерполяции и восстанавливается на выходе. Альфа исключена из glow.

### Новые параметры

| Параметр | Назначение и старт |
|---|---|
| `Gate Weave (px)` | Независимое дрожание позитива в кадровом окне по X/Y. Старт 0,8 px; 0,5–1 — деликатно, 2–4 — выраженно; 0 выключает. Пиксели полного выходного кадра, render scale/proxy учитывается. Весь позитив, зерно и повреждения перед Projector движутся вместе. |
| `Lamp Flicker` | Быстрые межкадровые изменения потока лампы в линейном свете. Старт 0,025; 0,02–0,035 — деликатно, 0,1 — заметно; 0 выключает. Резкая часть и glow мерцают совместно. |
| `Lamp Breathing` | Медленное дыхание яркости; старт 0,01, обычно 0,01–0,015; 0,05 — заметно; 0 выключает. Для настройки сначала отключите и настройте Flicker отдельно. |
| `Projector Seed` | Независимый seed лампы/транспорта; меняет рисунок, не влияет на Camera или зерно. |

Сглаживание AR(1) повторяет Comfy: X=0,55; Y=0,60 при силе 0,8×Gate Weave; быстрый свет=0,18; медленный=0,92. Каждый сигнал центрируется и нормируется по среднему квадратичному отклонению за диапазон Source. Lamp gain = max(0, 1 + flicker + breathing). На CPU кэшируются только четыре одномерных сигнала; сила контролов применяется после нормировки, поэтому настройка силы не создаёт новый шум. Нативный Box–Muller/counter hash отличается от Torch RNG/BLAKE2b; точного совпадения рисунка по seed с Python нет. Это межкадровая модель Comfy, без субкадрового обтюратора.

Время OFX уже измеряется кадрами: индекс = floor(time − Source start), без умножения на FPS. Сигналы проектора привязаны к кадрам показа и не наследуют cadence/seed ручки Camera. Одинаковые кадр, диапазон Source и seed воспроизводят результат при перемотке и нескольких экземплярах. Как и в Comfy, изменение длительности исходного диапазона меняет нормировку сигнала; trimming/retime в Resolve проверить отдельно. Projector следует применять на финальной сетке показа (например, 25 fps).

### Быстродействие

Без glow CPU работает одним проходом без полноразмерных промежуточных изображений; CUDA — одним kernel без scratch allocation. С glow CUDA обрабатывает RGB пакетными R2C/C2R FFT по двум осям, с тем же отражением крайних значений и спектральным откликом, без замены на обычный Gaussian. Четыре cuFFT-плана кэшируются на экземпляр по CUDA context/stream/размеру полного кадра; изменение размера glow не пересоздаёт планы. Рабочий блок выделяется из stream-ordered pool, буферы и FFT workspace переиспользуются между осями, освобождение ставится в ту же очередь. Основные плоскости занимают около 76 байт/пиксель плюс FFT workspace и небольшие пограничные массивы; картинки не кэшируются между actions.

При host stream render не ждёт GPU и не делает device-wide sync. При уничтожении экземпляра отдельный cleanup-поток ждёт только события последнего использования планов и освобождает их в соответствующем context; context/device потока Resolve не переключается. Если хост уже уничтожил context, он владеет освобождением оставшихся driver-ресурсов. Первое создание/JIT cuFFT-планов может быть дольше последующих кадров; скорость сравнивать после прогрева. Ошибки CUDA/cuFFT возвращаются с числовым кодом в лог, без попытки читать GPU pointers через CPU fallback.

Код 0.9, новые тесты и GPU-путь **не собирались и не запускались агентом**. Подготовлены `silentfilm_projector` (сигналы, линейный свет, flat-field glow, alpha, border, отмена) и `silentfilm_projector_cuda_parity` (CPU/FFTW vs CUDA/cuFFT, все transfer, lamp+glow, premultiplication, раздельные bounds, signed stride/padding/window, повторное использование планов, 1×1 и не степенные размеры, host stream и без него). GPU parity не проверяет интеграцию с Resolve и не доказывает совпадение с Torch RNG. Фактическое ускорение ещё не измерено.

Другие оптические параметры Projector из Comfy (отдельная softness и статическая vignette) пока не добавлены. Glow проверяйте после Print на позитиве с яркими точечными деталями на тёмном фоне; сравните strength 0, 0.1 и 0.3, затем несколько размеров. Ровное серое поле при включении glow должно сохранять яркость.

## Defects

В одном самостоятельном эффекте можно выбрать `Material Stage`:

| Этап | Подключение | Интерпретация |
|---|---|---|
| Capture / Camera | после Camera, перед Negative | частицы затеняют входную сцену в линейном свете |
| Negative | после Negative, перед Print | пыль затемняет пропускание; царапины открывают эмульсию |
| Printing | перед Print | загрязнение затеняет экспозицию печати |
| Positive | после Print, перед Projector | износ готовой позитивной копии |
| Projector Gate | после Projector | загрязнение неподвижного кадрового окна |

`Pattern`: Dust, Scratches, Stains или Development. `Strength` задаёт силу, `Size` нормируется по ширине кадра, `Amount` задаёт число частиц/линий, `Persistence` меняет рисунок после заданного числа физических кадров (OFX-время переводится по частоте выходного клипа), `Seed` обеспечивает повторяемость запроса. Форма масок и генератор native hash v1 намеренно независимы от Comfy `random.Random`/BLAKE2b, поэтому точные координаты и числовой seed рисунка между реализациями не совпадают. Выход стабилен для одинаковых времени, seed и параметров; кадры можно запрашивать в любом порядке.

Development создаёт гладкое детерминированное поле и действует как локальная плотность. Dust/Stains/Scratches имеют сглаженные границы. Альфа сохраняется. Эффект выполняется CPU; tiled rendering выключен.

## Пакетная проверка пользователем

1. Сконфигурируйте и соберите текущий bundle, выполните существующий CTest-набор.
2. Проверьте в Resolve наличие Projector и Defects, а также новые Camera и Halation controls у Negative/Print.
3. В новой Projector выключите Gate Weave/Flicker/Breathing/Glow и сравните с входом при правильном encoding. Затем на контрастной таблице включите Gate Weave=2: должна двигаться вся копия вместе с зерном, пылью и alpha, края не чернеют (border clamp). Верните 0,8.
4. На среднем сером выключите weave, включите Flicker=0,1 и Breathing=0; мерцание должно быть видно. Затем Flicker=0 и Breathing=0,05: яркость меняется плавнее. Верните 0,025 и 0,01. Включите Glow=0,1 на яркой детали в тёмном кадре — ореол и основное изображение меняют яркость вместе, без отдельной пульсации доли glow. При выключенной лампе flat-field glow сохраняет яркость.
5. Проверьте seed, обратную перемотку и несколько экземпляров, первый/последний кадр, proxy/full resolution, Color/Fusion, полупрозрачный RGBA, короткий экспорт, отмену и повторный запуск. Удаление ноды/закрытие проекта не должно зависать на освобождении FFT-планов. Для диагностики включите `ALEXZ_SILENTFILM_OFX_TRACE=1`: ожидается `CUDA projector ... shift=... lamp=... glow=...`. CPU в логе означает выбор CPU-буферов хостом. Сравнивайте скорость одного и того же отрезка без готового Render Cache и трассировки, отдельно при Glow=0 и 0,1. Отключайте трассировку для замеров.
6. Defects: проверьте все пять Material Stage; поочерёдно включите каждый Pattern, смените Seed, перемотайте время назад и повторно запросите то же время. Рисунок должен быть детерминированным; при смене события после Persistence он может измениться.
7. Defects пока остаётся CPU; Projector 0.9 и Camera объявляют CUDA-поддержку. В CUDA build ожидаются семь CTest, включая новый CPU Projector и Projector CUDA parity. Запускает пользователь после успешного build.

Агент не запускал сборку, CTest или Resolve; прохождение этих сценариев не заявлено.
