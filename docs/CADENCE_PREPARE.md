# Подготовка каденса с настоящей сменой длительности — 0.10

## Что реализовано

Это отдельная команда подготовки материала: Lua-окно в Resolve запускает нативный `silentfilm_cadence` в отдельном процессе. В процесс Resolve не добавляются FFmpeg, Python, PyTorch или ComfyUI. При запуске дочернего процесса Lua удаляет только для него LD_LIBRARY_PATH/LD_PRELOAD, чтобы bundled-библиотеки Resolve не подменяли системные FFmpeg/libstdc++; окружение самого Resolve не меняется. Используется общее C++-ядро расписания и CPU/CUDA-рендер Camera.

Для каждого виртуального кадра плёнки создаётся ровно одна экспозиция. Если получилось M экспозиций, записывается M кадров; длительность при показе в 25 fps равна M/25. FPS вывода не участвует в расписании съёмки. Стандартные десятичные обозначения 23,976/29,97/59,94 приводятся к соответствующим частотам с делителем 1001 для правильных timestamp; базовая проверка делается на целых 25 fps. Нет нормировки к старой длине клипа и повторов ради её сохранения. Например, при постоянных 20 fps из секунды исходника получится 20 кадров, которые займут 0,8 с при показе в 25 fps. Для плавающего FPS число кадров определяется расписанием; арифметическое среднее границ для расчёта не используется.

Время источника задаётся индексами кадров CFR-файла. Середина экспозиции и треугольные shutter weights соответствуют простому режиму Comfy; optical flow пока отсутствует. Выдержка, компенсация экспозиции, shake, монохром, виньетка, краевой расфокус, softness и focus drift запекаются на этом этапе. Focus signal и pose общие с OFX. Seed/hash остаётся нативным, точного совпадения с Torch/Python RNG нет.

**Состояние на 2026-11-07:** пользователь завершил сборку и CTest **9/9 PASS**, включая native CPU export ProRes/TIFF, точное сокращение 25→20 кадров и In/Out, Camera timing и все CUDA parity. Финальный device link подтверждён. Реальный Lua UI/SDK, GPU-экспорт helper end-to-end, импорт, цвета/alpha/transfer и скорость в Resolve ещё требуют проверки. Агент сборки/тесты/Resolve не запускал. После PASS подготовлено только устранение FFmpeg deprecation warning; оно ждёт следующей обычной сборки и не мешает использовать текущий проверенный бинарник.

## Исходник и область действия

- Откройте нужную папку **Media Pool**, нажмите в окне «Обновить список» и выберите исходник в выпадающем списке. Чтение UI-выделения через GetSelectedClips больше не используется: на пользовательской установке оно не возвращало один клип. Можно также ввести полный путь к обычному видео и нажать «Принять путь»; в этом варианте пересчитывается весь файл без In/Out Media Pool. Выделение клипов Edit не используется.
- Для клипа из выпадающего списка по умолчанию используются **In/Out Media Pool**: `in` включительно, `out` включительно, индексы относительно начала файла. Без In/Out пересчитывается весь файл; только In означает от In до конца.
- Эффекты, ретайм, CST и цветокоррекция таймлайна в этот файл не входят. Нужный обработанный материал сначала экспортируйте из Resolve в отдельный промежуточный клип.
- Нужен CFR SDR Rec.709 с квадратными пикселями. В окне явно выберите кодирование исходника: sRGB, Gamma 2.4 или Linear Rec.709. Вход приводится к sRGB, как ожидает ядро Camera. Выход тоже sRGB; при использовании CST/управления цветом учитывайте этот контракт.
- Известные HDR PQ/HLG и другие первичные, VFR/разрывы timestamps, поворот display-matrix и несовпадение FPS Clip Attributes с закодированным FPS отвергаются с сообщением. Автоматического угадывания Log/HDR или запекания поворота нет. Для RAW, compound/timeline и image-sequence источников подготовьте обычный CFR-файл через Resolve.
- Выход первой версии **без звука**. Камера уже запечена: после импорта добавляйте **Negative → Print → Projector**, повторная Camera не нужна.

Новый результат импортируется в Media Pool и **новый таймлайн** с заданным FPS. Исходный монтаж и файлы не заменяются. Это проверяемая первая версия метода, а не непосредственное изменение скорости существующего Edit-клипа.

## Зависимости и сборка пользователя

Нативному процессу нужны SDK-библиотеки FFmpeg; OFX-модуль с ними не линкуется. Для Debian/Ubuntu:

```bash
sudo apt update
sudo apt install pkg-config libavformat-dev libavcodec-dev libavutil-dev libswscale-dev ffmpeg
```

FFTW3 и CUDA остаются по `DEPENDENCIES.md`. Используйте системные CMake/C++17, без `conda run`.

```bash
cd /home/alex/Projects/ALEXZ_SilentFilm_OFX
cmake -S . -B build-cuda -DCMAKE_BUILD_TYPE=Release -DSILENTFILM_ENABLE_CUDA=ON -DSILENTFILM_BUILD_CADENCE=ON -DCMAKE_CUDA_COMPILER=/usr/local/cuda/bin/nvcc -DCMAKE_CUDA_ARCHITECTURES=86
cmake --build build-cuda --clean-first --parallel 2 && ctest --test-dir build-cuda --output-on-failure
```

`--clean-first` здесь нужен также для предыдущего изменения RDC/device link. Тесты должны запускаться только после успешной сборки. В конфигурации с CUDA, helper и системными ffmpeg/ffprobe ожидается **9 тестов**: семь прежних, `silentfilm_cadence` и `silentfilm_cadence_export`. Без CLI интеграционный тест не добавляется; без CUDA остаются CPU-тесты. Пользовательский полный прогон 0.10 подтвердил 9/9 PASS; новое устранение FFmpeg warning сделано после этого прогона.

Основные артефакты:

```text
build-cuda/bin/silentfilm_cadence
build-cuda/scripts/SilentFilm_Cadence.lua
```

Helper и Lua можно собирать отдельно: `cmake --build build-cuda --target silentfilm_cadence --parallel 2`. Если утилита не нужна для OFX-сборки, укажите `-DSILENTFILM_BUILD_CADENCE=OFF`. Первая версия Lua/CLI подготовлена только для Linux; Windows/macOS не проверены.

## Первый запуск из Resolve

Устанавливать новый OFX bundle для самой команды подготовки не требуется. После успешной сборки, в Console Resolve переключитесь на **Lua** и выполните:

```lua
dofile('/home/alex/Projects/ALEXZ_SilentFilm_OFX/build-cuda/scripts/SilentFilm_Cadence.lua')
```

Для постоянного пункта Workspace → Scripts пользователь может скопировать **сгенерированный** файл (не `.lua.in`) в каталог своих скриптов:

```bash
mkdir -p "$HOME/.local/share/DaVinciResolve/Fusion/Scripts/Utility"
cp build-cuda/scripts/SilentFilm_Cadence.lua "$HOME/.local/share/DaVinciResolve/Fusion/Scripts/Utility/"
```

По SDK меню скриптов сканируется при запуске Resolve; до следующего запуска используйте `dofile`. Агент ничего не копирует в Resolve и не перезапускает его. Сгенерированный скрипт содержит пути именно этой сборки; после перемещения workspace или выбора другого build заново сгенерируйте/скопируйте Lua.

1. Откройте папку исходников Media Pool и при необходимости задайте In/Out нужного клипа. В окне нажмите «Обновить список» и выберите файл в выпадающем списке. Либо введите абсолютный путь и нажмите «Принять путь» (весь файл, без Media Pool In/Out).
2. Для первой проверки возьмите участок **1 секунду при 25 fps** (25 исходных кадров). Задайте Min=Max=20, Variation=0, Irregularity=0, Motion Blur=0, Samples=1, Exposure Link=0, Shake=0. Для простой картинки также выключите Vignette/Edge Softness/Global Softness/Focus Drift.
3. Выберите вывод ProRes 4444 MOV, расчёт CUDA и FPS показа 25. Папка по умолчанию — `renders/cadence` внутри проекта; отдельная уникальная папка создаётся для каждого запуска.
4. Нажмите «Рассчитать». Расчёт идёт в фоне; окно остаётся доступным. **Статус обновляется кнопкой «Проверить / импортировать»**, автоматического таймера в первой версии нет. Закрытие окна не останавливает процесс; путь задания сохраняется для следующего открытия.
5. Во время расчёта та же кнопка показывает статус и число записанных кадров. После готовности она импортирует результат и создаст новый таймлайн. Должно получиться **20 кадров / 0,8 с** при 25 fps, а не 25 кадров / 1 с. FPS и длительность TimelineItem читаются обратно и проверяются; при ошибке создания новый таймлайн откатывается, файл/Media Pool result сохраняются.
6. Затем попробуйте Min=16/Max=22, Variation=1 и отдельный прогон Min=10/Max=30. Включайте выдержку, экспозицию, shake и оптику по одному. Число кадров и скорость должны зависеть от реального расписания, без дополнительного Speed Change.
7. Сравните CPU и CUDA на одном коротком источнике/диапазоне/настройках. Проверьте изменение output FPS 25 → 24: число экспозиций и их карта должны остаться одинаковыми, изменится только длительность показа.
8. Проверьте In/Out, первый/последний кадр, seed, alpha, отмену и повторный запуск. Пункт «Остановить» создаёт запрос отмены; native-процесс проверяет его между операциями и через callback декодера/CPU render. Текущая запись файла/кодирование или GPU-кадр могут сначала завершиться. Частичный результат не импортируется.

Для TIFF отключите в Media Pool **Show Individual Frames**, чтобы кадры импортировались как одна последовательность. Если Resolve не импортирует ProRes из текущего FFmpeg, повторите короткий тест в TIFF и передайте `render.log`. Поддержка формата данной установкой Resolve пока не подтверждена.

## Форматы и производительность

- **ProRes 4444 MOV** — рабочий однофайловый вариант. Кодирует `prores_ks`, профиль 4444, вход encoder YUVA444P10. Сжатие с потерями; не обещает побитового совпадения с float Camera. RGB sRGB преобразуется в limited-range YUV с матрицей BT.709 и тегами primaries BT.709 / transfer sRGB. Alpha сохраняется, но точность рабочего pixel format ограничена 10 битами.
- **TIFF RGBA16** — uncompressed little-endian, unsigned 16 бит/канал, straight alpha (ExtraSamples=2), без потерь после квантования float → 16 bit. Значения ограничиваются SDR 0–1. Объём заметный: 1920×1080 RGBA16 — примерно 16,6 MB на кадр, плюс заголовок; 190 кадров — около 3,15 GB. TIFF не имеет встроенного FPS, его назначает импортёр и проверяет чтением Clip Attributes.

Декодирование и кодирование работают через системные FFmpeg-библиотеки **в отдельном процессе**, на CPU. Тяжёлая Camera обрабатывается CUDA при явном выборе CUDA; ошибки GPU не подменяются тихим CPU fallback. Для декодера/encoder используются ограниченные пулы потоков.

Источник не загружается целым видеобатчем. Декодер хранит ограниченный raw-frame cache (`cache_mib`, по умолчанию 1024); GPU кэширует загруженные кадры (`gpu_cache_mib`, по умолчанию 512), чтобы не отправлять одинаковую пару для каждого отсчёта заново. Активная экспозиция и buffers Camera занимают память сверх cache budget. При слишком широком shutter/высоком source FPS и маленьком raw cache процесс явно сообщает об отсутствии нужного кадра; бюджет можно увеличить в request.ini нового задания.

Декодирование точного In пока идёт последовательно от начала файла: это сохраняет точность индексов и проверку CFR без предположений о keyframes/timecode. Конвертируются и загружаются в GPU только нужные кадры. Выгружается один законченный Camera-кадр для encoder; собственный stream синхронизируется перед чтением CPU. Это допустимо для отдельного процесса и не меняет правило асинхронного host stream в OFX. Кодирование/запись выполняются в отдельном worker-потоке с ограниченной очередью и передачей кадров без полноразмерного копирования, параллельно со следующим decode/GPU capture.

Реальная скорость пока не измерена. Её могут ограничивать декодер, encoder или диск, особенно в TIFF. Изменение FPS показа не пересчитывает математику съёмки, но новый экспорт пока запускается новым заданием; переинтерпретацию уже готовых кадров можно сделать вручную Clip Attributes.

## Паспорт, лог и повторный импорт

В каталоге задания находятся:

```text
request.ini       параметры съёмки, диапазон, FPS показа, формат и backend
context.ini       имя исходного проекта/клипа для Lua-импорта
status.ini        атомарно обновляемый статус
render.log        вывод native/FFmpeg/CUDA
capture_map.csv   output index, границы экспозиции, capture FPS, центр, выдержка, gain
result.ini        только успешно завершённый результат и точное число кадров
cadence.mov       или frames/frame_00000000.tif …
```

Окно позволяет ввести путь прежнего задания и повторить «Проверить / импортировать». В том же окне повторный импорт защищён; при новом открытии его можно импортировать ещё раз в новый таймлайн. Параметры из существующей OFX Camera автоматически не считываются — задайте их в окне, снимок сохранится в request.ini. Смена настроек создаёт новое задание и не перезаписывает прежнее. Native lock-directory защищает от одновременного запуска одного задания; после аварийного завершения используйте новую папку. Исходные файлы не удаляются и не заменяются.

Для запуска подготовленного request вручную (в новом каталоге задания) пользователь может выполнить:

```bash
build-cuda/bin/silentfilm_cadence --job /absolute/path/to/job/request.ini
```

Пример минимального request:

```ini
schema=1
input=/absolute/path/source.mov
device=cuda
format=prores
output_fps=25
fps_min=16
fps_max=22
variation=0.7
irregularity=0.15
seed=1925
shutter=0.65
motion_blur=0.8
samples=5
exposure_link=1
shake=0.25
```

`start_frame=0` и `frame_count=0` означают весь файл; ненулевая frame_count — точное количество исходных кадров, не выходных. Поля неизвестной версии/опечатки отвергаются. Вручную также доступны `expected_source_fps`, `input_transfer=srgb/gamma24/linear`, `gpu_index`, `cache_mib`, `gpu_cache_mib`, параметры оптики `vignette/edge_softness/softness/focus_drift/focus_seed/edge_start/edge_end`. Чтобы повторно запустить расчёт, создайте новую папку без result/movie/frames; готовый результат не перезаписывается.


## Если после «Рассчитать» ничего не видно

Строка «Расчёт идёт в отдельном процессе. Окно можно закрыть…» — постоянная подпись, она не подтверждает запуск. В обновлённом Lua реальный статус находится **вверху**, а этапы и ошибки печатаются в Console с префиксом `[SilentFilm Cadence]`. Закройте старое окно, выполните dofile заново, выберите файл в списке текущей папки Media Pool или по полному пути, затем нажмите «Рассчитать». Первое сообщение должно быть «Нажата кнопка…», затем создание задания и запуск процесса; при сбое будет traceback. Если стандартная папка job не создана, нужно сообщение этапа/ошибки, а не повторный запуск native render агентом.


После повторной ошибки GetSelectedClips интерфейс изменён: источник выбирается явно из `GetCurrentFolder():GetClipList()` или по пути. Удалена зависимость от selection/focus Media Pool. Обновлены template и уже сгенерированный Lua; достаточно закрыть старое окно и повторить dofile, без C++ build. Новый выбор ещё требует пользовательской проверки; успешный native старт из UI пока не подтверждён.


## Повторить импорт без рендера

Готовое задание с `result.ini` не нужно пересчитывать после исправлений Lua. Откройте обновлённое окно, в поле «Задание» укажите каталог завершённого job и нажмите «Проверить / импортировать». Импортёр добавляет весь подготовленный клип, без ручного диапазона кадров, и сверяет TimelineItem duration с M. Console показывает Media Pool FPS/Frames/Duration, Project/Timeline FPS и фактические start/end/duration. Если проверка не прошла, эти числа нужны для диагностики; native-файл остаётся сохранён.
