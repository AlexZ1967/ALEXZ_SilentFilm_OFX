## Разделение

В приложении: FPS Min/Max, вариация/нерегулярность ручки, seed, выдержка, смаз и число отсчётов, связь экспозиции с ручкой, движение камеры внутри выдержки, диапазон исходника и FPS показа. Временная выдержка и связанная с ручкой экспозиция рассчитываются и запекаются в RGB-кадры Cadence. На выходе M цветных кадров; длина = M / FPS показа. Звук не сохраняется.

Полная сверка контролов, их групп и действия: [CAMERA_PARAMETER_SPLIT.md](CAMERA_PARAMETER_SPLIT.md).

В **SilentFilm Camera Optics** группа **Vignette and Edge Blur** содержит `vignette_strength`, `edge_start`, `edge_end`, `edge_softness`; группа **Focus and Softness** — `softness`, `focus_drift_strength`, `seed`. Начало/конец маски общие для виньетки и краевого расфокуса, `edge_end` должен быть больше `edge_start`. Эффект принимает только основной видеоклип и обрабатывает текущий кадр; он не рассчитывает движение ручки, выдержку или экспозицию. **SilentFilm Camera** и её ID сохранены для старых проектов и preview.

Cadence интегрирует RGB-выдержку с движением камеры, затем применяет экспозиционный gain в линейном sRGB с SDR clamp и кодированием обратно в sRGB. Camera Optics применяет выбранную статическую оптику к результату Cadence и выдаёт монохромное изображение.

Camera Optics не читает sidecar-файлы и не имеет параметров выбора файлов. Между каденсом и оптикой сохраняется обычный видеоклип. После промежуточного файла побитовая идентичность не обещается: TIFF RGBA16 даёт квантование, ProRes 4444 — также потери кодека. Вход Camera Optics должен оставаться **sRGB / примарии Rec.709**; цветоуправление Resolve требуется согласовать с этим контрактом.

## Подготовка Linux

### Интерполяция движения

В окне Cadence добавлен выбор **`blur_mode`**. По умолчанию выбран **`flow_integrated`** (`blur_mode=flow_integrated`), альтернативный режим — **`simple`** (`simple`). Начальное число **`blur_samples`** — 9, как в Comfy Camera. Flow применяется к каждой дробной позиции отсчёта выдержки до shake и усреднения; даже при одном отсчёте центр может оставаться дробным.

Перенесён CPU-алгоритм Comfy: grayscale 0,299/0,587/0,114 с усечением в uint8; оценка Farneback в обе стороны на длинной стороне до 640 px, параметры 0.5/3/17/3/5/1.1/0; увеличение поля со масштабированием векторов; OpenCV remap с bilinear/BORDER_REPLICATE. Проверка обратного потока, контроль несовпадения RGB-контуров и сглаженная маска 5×5 ослабляют деформацию на перекрытиях и в ненадёжных областях. Там результат возвращается к простому смешиванию. Это защита из референса, а не гарантия отсутствия любых артефактов на произвольном быстром движении.

В редакции 0.13.1 добавлена точная защита неподвижного кадра: если RGB двух исходных кадров полностью совпадает, Farneback/remap не вызываются, RGB сохраняется без изменений. Отличающаяся alpha интерполируется на исходных координатах. Сравниваются исходные float RGB без epsilon и без uint8-квантизации: слабое реальное движение этим условием не подавляется. После исправления пользователь подтвердил успешный прогон без ошибок; полный лог и число выполненных тестов не предоставлены.

Для flow нужен системный `libopencv-dev`; команды находятся в [DEPENDENCIES.md](DEPENDENCIES.md). При выбранном CUDA Farneback оценивает поле на CPU до 640 px, как в Comfy; деформация, confidence/маски, их сглаживание и смешивание выполняются CUDA-ядрами, затем движение камеры, интеграция выдержки и экспозиция также идут на GPU. Исходники и пары кэшируются, доступная VRAM проверяется между экспозициями. Поля потока кэшируются максимум для четырёх соседних пар с ограничением по бюджету, отдельные CUDA-буферы отсчётов переиспользуются. `status.ini`/`result.ini` сохраняют `blur_mode` и фактический `flow_backend`. Старые задания без `blur_mode` остаются в режиме `simple`.

В отсутствие OpenCV запрос flow завершается понятной ошибкой, без скрытого отключения. Окно проверяет `silentfilm_cadence --capabilities` перед подготовкой кадров Resolve, чтобы не запускать дорогой экспорт для неподдержанного режима. Пользователь подтвердил успешные тесты после исправления 0.13.1. Визуальное сравнение с Comfy и скорость нового режима ещё не проверены.

Окно использует **GTK 4 + Pango** через системный PyGObject. Tkinter больше не нужен. Debian/Ubuntu, устанавливает пользователь:

```bash
sudo apt install python3-gi python3-gi-cairo gir1.2-gtk-4.0
```

Команда установки соответствует [официальной инструкции PyGObject](https://pygobject.gnome.org/getting_started.html). [Pango](https://www.gtk.org/docs/architecture/pango) обеспечивает текстовую разметку GTK; в окне используются Unicode-переносы и сокращение длинных путей. Системные шрифты/масштабирование наследуются от окружения рабочего стола.

Conda/PyTorch/pip-пакеты не нужны. Python не добавляется в OFX/GPU-ядро. `/usr/bin/python3` обслуживает окно, отдельный `/opt/resolve/bin/ResolvePython` — подключение к Resolve. GTK/Pango загружаются только в процесс окна; внешний bridge использует совместимый с Resolve интерпретатор. OFX не получает зависимостей GTK/Pango. Используется базовый API GTK 4.0 без обязательной libadwaita. Справка: `/opt/resolve/Developer/Scripting/README.md`, Local Scripting.

Первый вариант подготовлен для **Linux x86_64, Resolve Studio 21.1+** с bundled ResolvePython и GetSettings/SetSettings. Это требования реализации; runtime-совместимость ещё не подтверждена. Windows/macOS launcher пока не поддерживает.

В Resolve включи **Preferences → System → General → External scripting → Local**, открой проект. Network не требуется. Если настройка требует перезапуска, его выполняет пользователь.

## Работа с выбранными клипами таймлайна

Галочка **«Use Raw Source (In/Out Only)»** включена по умолчанию и сохраняется в настройках и пресетах. Она читает напрямую подрезанный участок исходного файла: без цветокоррекции, OFX, Fusion, трансформаций и изменения скорости монтажного экземпляра. Подготовка кадров через Resolve пропускается; результат возвращается в тот же монтаж обычным способом. Интерпретацию FPS задаёт source_fps_mode. Проверь **Input Transfer** по исходному файлу.

1. На Edit выдели один или несколько видеоклипов и запусти **Workspace → Scripts → Utility → SilentFilm Cadence**. Окно появится сразу. Связанное выделенное аудио игнорируется при создании очереди. Выделение обновляется в простое и повторно читается перед **Calculate**; до нажатия кнопки расчёт не начинается.
2. Для каждого монтажного экземпляра фиксируются его ID, дорожка, позиция и source In/Out. Разные использования одного файла обрабатываются отдельно. В обоих режимах вход содержит `end−start` кадров при FPS таймлайна, начиная с нуля; поля диапазона доступны только для чтения.
3. Настрой ручку/выдержку/shake и размещение: **Replace Selected Clip** или **Add Above Source**. Настройки общие для очереди; автоматический `source_fps_mode=source` берёт FPS исходника каждого клипа. При замене короткий результат оставляет промежуток; длинному нужно свободное место. Add Above Source ищет ближайшую незаблокированную дорожку выше, свободную на всю длину результата, включая отключённые дорожки. Их видимость не меняется. Если места нет, создаётся верхняя дорожка. Позиции остального монтажа сохраняются, новый таймлайн результата не создаётся.
4. Нажми **Calculate**. Очередь идёт слева направо по позиции начала; при одинаковом начале — от нижней дорожки к верхней. Выбор и параметры не меняются между заданиями. Окно показывает текущий клип, его прогресс и общий прогресс очереди.
5. С Use Raw Source native helper читает исходный файл напрямую. Без этой галочки provider получает только нужные кадры с обработками через `TimelineItem.ExportFrame`, передаёт PNG в памяти и кэширует повторные запросы. Render Queue и промежуточный FFV1 в новом пути не используются. PNG декодируется на CPU; CUDA выполняет деформацию и интеграцию экспозиций. Подробности — [CADENCE_FRAME_PROVIDER.md](CADENCE_FRAME_PROVIDER.md).
6. Каждый готовый файл получает имя исходного клипа с `_cadence` и отдельную папку задания. При включённом автоимпорте сначала заканчивается импорт текущего результата, затем начинается следующий клип. При выключенном автоимпорте все результаты сохраняются в файлы без изменения монтажа.
7. Перед заменой создаётся служебный backup. Удаляется только выбранное видео без ripple; результат ставится в ту же позицию, проверяются длительность и позиции остальных video/audio/subtitle. Аудио не пересчитывается. После успешной проверки backup удаляется; при ошибке сохраняется для восстановления.
8. Ошибка или **Cancel** останавливает очередь: готовые результаты сохраняются, оставшиеся клипы пропускаются. Уже начатый импорт может завершиться. При закрытии окна текущий native-процесс может продолжиться отдельно, но следующие клипы автоматически не запускаются. Отчёт о каждом клипе и пути заданий записываются в `<Output Folder>/batch_reports/batch_*.json`. Автоматическое возобновление всей очереди после закрытия пока не реализовано; отдельное задание можно открыть обычным способом.
9. Во время очереди не меняй монтаж и обработки исходных клипов. Перед каждым заданием и импортом проверяется сохранённый монтажный экземпляр. Для дальнейшей оптики добавь **Camera Optics**, затем нужные Negative/Print/Projector; запечённые обработки повторно накладывать не нужно.

## Цвет и границы первой версии bake

В поле **«Input Transfer»** для timeline source по умолчанию **«Авто (из Resolve)»**. Пустое optional поле таймлайна не затирает известную гамму проекта; предусмотрен read-only запрос split/combined значений через GetSetting для версий API, где bulk GetSettings их не возвращает. Если API всё равно не сообщает гамму, выбери фактическое значение из **Project Settings → Color Management** (например, Rec.709 Gamma 2.4). Это явное подтверждение кодирования, не CST: существующую sRGB/Log гамму нельзя объявить Gamma2.4 без преобразования. Неизвестная гамма по умолчанию не угадывается. Для raw файла Auto недоступно; кодирование задаётся явно.

Автоматический bake подготовлен для **DaVinci YRGB, SDR Rec.709**, рабочая гамма **Gamma 2.4 / sRGB / Linear**. Color Managed, ACES, другая гамма/примарии и обнаруженный глобальный output/timeline LUT останавливают автоматическую подготовку: пока нет проверенного контракта возврата без повторной цветовой обработки. Gamma не угадывается по изображению. GammaTag/ColorSpaceTag сами по себе не являются преобразованием цвета. Native reader по-прежнему проверяет CFR/SDR/metadata.

Нужен файловый видеоклип с доступным MediaPoolItem; неподдержанные генераторы/compound/sequence без обычного файла отклоняются. Переходы/перекрытие на целевом клипе и заблокированная V-дорожка останавливают операцию до удаления. Обработка, зависящая от отключённых других видеодорожек, не является полным видимым композитом. Реальную полноту OFX/Fusion/alpha, единицы MarkIn/Out при разных project/timeline FPS и изоляцию timeline grade надо проверить в установленном Resolve. После сохранения рабочего preset могут остаться неоткрытые API настройки качества/cache; битовую идентичность Viewer/Deliver обещать нельзя.

Во время задания не меняй исходную обработку: snapshot проверяет ID/границы/позицию/постоянный speed, но API не предоставляет полный hash всех OFX/Fusion/grade параметров. Работа ведётся на копии, исходные эффекты не удаляются при подготовке. Если API дал сбой после начала финальной замены, приложение пытается открыть backup; исходный таймлайн может остаться частично изменённым. `replace_recovery.json` сохраняет backup. При нехватке места для замены выбери «Add Above Source»: результат займёт свободный интервал ближайшей подходящей дорожки выше источника; если такого интервала нет, создастся одна новая верхняя дорожка.

## Имена результата

`Scene_01.mp4` → **`Scene_01_cadence.mov`**. Берётся имя монтажного клипа (`TimelineItem.GetName()`). Временное `processed.mov` не влияет на имя результата. Клип Media Pool получает то же имя без расширения. Недопустимые для переносимого имени символы заменяются `_`, Unicode сохраняется, длина ограничена; повторный `_cadence` не добавляется.

TIFF: `frames/Scene_01_cadence_00000000.tif` и далее, в `result.ini` сохраняется соответствующий pattern. Native request получает необязательный `output_name`; без него старые CLI/Lua задания сохраняют прежние `cadence.mov` / `frame_%08d.tif`.

## Хранение результатов и очистка

**Output Folder** запоминается и входит в пресеты. Структура: корень / название проекта с ID / название клипа_cadence_ID. **Clean Timeline Cache** очищает неиспользуемые генерации текущего таймлайна, **Clean Project Cache** — всего проекта. В обоих режимах проверяются все таймлайны проекта; удаляемые результаты убираются и из Media Pool. Список и объём показываются перед подтверждением. Подробности и ограничения — [CADENCE_CACHE.md](CADENCE_CACHE.md).

## Настройки и пресеты

Корректные настройки автоматически сохраняются через 0,6 секунды после изменения и при закрытии окна. **Preset** выбирает именованный пресет; **Custom** обозначает изменённые значения. Введи имя в **Preset Name** и нажми **Save Preset**. Перезапись существующего имени требует подтверждения. **Factory Reset** возвращает заводские значения, включая Output Folder, сохраняя именованные пресеты и выбранный монтажный клип.

Сохраняются параметры съёмки (включая target_fps_min/max, fps_drift_strength), обработки и экспорта, размещение, Auto Import, Use Raw Source, Output Folder, source_fps_mode и ручной source_fps. В timeline/source фактический FPS берётся из метаданных и не затирает сохранённое ручное число для custom. Размеры, подрезка, путь исходника и фактический FPS таймлайна/исходника в пресет не входят.

Хранилище: `$XDG_CONFIG_HOME/ALEXZ/SilentFilm/cadence_settings.json`, по умолчанию `~/.config/ALEXZ/SilentFilm/cadence_settings.json`. Запись атомарная; некорректный ввод не заменяет последний корректный файл. Повреждённый файл сохраняется как `.invalid-*` перед следующей записью. Для применения Python-изменений достаточно переоткрыть приложение; копирование и rebuild helper не нужны. Проверки 0.16 агентом не запускались.

Старые результаты **full_camera/Lua** уже содержат запечённую камеру. Для нового режима Camera Optics не требует карты, нумерации кадров или других файлов.

## Продолжение и ошибки

После закрытия окна уже запущенный рендер Resolve или native процесс продолжится, но переход к следующему этапу требует открытого GUI. Открой папку через **«Open Job…»**. Если bake не завершён или готов и native ещё не стартовал, нажми **«Calculate»** для продолжения сохранённого задания. Само открытие окна/папки не запускает тяжёлую обработку. Если native уже идёт, GUI только подключается к статусу; законченный результат импортируется кнопкой **«Import»**.

`pending_native.json` хранит параметры до появления обработанного входа; `request.ini` публикуется перед native запуском. `bake_state.json` хранит статус подготовки кадров; `resolve_processed.mkv` — промежуточный файл, `resolve_frames.log` и `ffmpeg_frames.log` — журналы. Отмена записывает `cancel.request`. Исторические задания старого пути могут хранить очередь и временный таймлайн.

`resolve_import.json` запоминает успешную операцию, проект/таймлайн; повторное нажатие не выполняет замену второй раз и не создаёт дубль. Для нового монтажа используй новое задание. После удаления отдельного созданного таймлайна его можно импортировать заново.

Без Resolve можно отключить автоимпорт и обработать файл отдельно. Поздний импорт выполняется в открытый проект; если задание уже привязано к ID проекта, только в него. Если процесс завершился без `result.ini`, смотри `render.log` через **«Show Folder»**. Прежний Lua launcher сохранён, для нового сценария он не нужен.
