## Как пользоваться

После сборки и обновления bundle в Camera Optics, Negative, Print, Projector, Defects, прежней Camera и Crank Exposure появится закрытая группа **My Presets**:

1. Настрой ноду и введи своё имя в **Preset Name**, например `Мягкая пыль`.
2. Нажми **Save / Overwrite My Preset**. Пресет с этим именем сохраняется для данного типа эффекта. Повторное сохранение заменяет файл; Preset Status показывает путь.
3. На другом экземпляре того же эффекта нажми **Refresh My Presets**, выбери вариант в активном списке **Saved Presets**, затем **Apply My Preset**. Save автоматически обновляет список текущей ноды; после открытия проекта сначала нажми Refresh. Выбор назначает имя/путь, но сам не меняет изображение. Альтернативы: ввести имя вручную или выбрать `.sfpreset` кнопкой обзора **Preset File**.

Сохраняется полный снимок художественных числовых настроек текущего кадра: включая Blend, материал, рисунок, Damage Model, seed, размеры, временные параметры и Encoding, если эти параметры есть у эффекта. Reference Preset и кнопки/UI-настройки в снимок не входят. Кривые анимации и выражения не экспортируются. Если у целевых параметров есть ключи, Apply отказывается менять ноду до каких-либо правок; применяй такой пресет на новом экземпляре без ключей. С анимированного источника Save сохраняет текущие значения, а не кривые.

**Crank Exposure — особый случай:** пользовательский пресет сохраняет только Blend. Exposure Map и Frame Offset остаются связанными с конкретным Cadence-клипом, не подменяются чужими данными. Это не индивидуальный Color DRX: тот по-прежнему генерируется в папке Cadence-результата с картой данного клипа.

Библиотека доступна во всех проектах этого пользователя. Ноды разных типов хранят файлы в разных папках, поэтому одинаковые имена Negative/Print не конфликтуют. При загрузке проекта пресеты сами не применяются, сохранённые параметры нод остаются в проекте. Исчезновение библиотечного файла не меняет уже настроенную ноду. Host Probe — диагностический эффект, библиотека в него не добавлена.

## Где хранятся файлы

По умолчанию Linux:

```text
~/.local/share/ALEXZSilentFilm/ofx-presets/
  com.alexz.silentfilm.defects/
    Мягкая пыль.sfpreset
  com.alexz.silentfilm.negative/
    Мой негатив.sfpreset
```

Если задан абсолютный `XDG_DATA_HOME`, используется `$XDG_DATA_HOME/ALEXZSilentFilm/ofx-presets/`. При отсутствии библиотеки чтение списка не создаёт папок; Save создаёт нужную. Чтобы перенести пресет на другой компьютер, скопируй `.sfpreset` в одноимённую папку типа эффекта и нажми Refresh. Имя файла и имя внутри паспорта должны совпадать: для переименования удобнее загрузить, ввести новое Preset Name и сохранить заново. Удалить вариант можно как обычный файл с последующим Refresh.

Формат — ограниченный версионированный текст, без Python/JSON-библиотек в OFX. Сохраняются типы и double с17 значащими цифрами. Запись через отдельный временный файл и rename; ошибка записи не должна повредить прежний пресет. Сохранение библиотеки не откатывается Undo монтажа. Профили будущей версии с другим набором параметров требуют явной совместимости/миграции: текущая загрузка отклоняет несовпадающую схему.

Чтение/запись выполняются только на UI actions; CreateInstance не читает библиотеку. Saved Presets обновляется после Save и по Refresh одним непустым массивом ChoiceOption, без propReset; индекс предварительно возвращается0, устаревшие слоты становятся нейтральными «—». Save записывает файл и назначает Preset File. CreateInstance не сканирует библиотеку и не меняет список. В Render нет дисковых обращений к библиотеке или дополнительных вычислений. Все пути — UTF-8 строки, POSIX storage отделён от вычислительного ядра. Изменение имени/списка/статуса помечено EvaluateOnChange0. Apply проверяет всю схему, типы, конечность и диапазоны до правок, затем объединяет изменения в один paramEditBegin/End. Ошибка host setter восстанавливает исходные значения; отказ rollback явно показывается. UI callbacks защищены от рекурсии.

## Проверки пользователя

```bash
cd /home/alex/Projects/ALEXZ_SilentFilm_OFX
cmake --build build-cuda --parallel 2 &&
ctest --test-dir build-cuda --output-on-failure
```

Добавлен `silentfilm_user_presets`: точность снимка, Unicode, разделение типов эффектов, overwrite/отсутствие временных файлов, неправильные имена/числа/дубли/версия/усечённые файлы/чужая нода/символические ссылки. Эти тесты проверяют storage, не host UI. В сборку0.31 также входят пока не проверенные пользователем изменения Defects0.30; [их независимое сравнение](DEFECTS_COMFY_0.30.md) остаётся актуальным.

В0.33 `silentfilm_ofx_preset_lifecycle` проверяет полный Camera Optics Save с русским именем без изменения Choice и без host metadata reads, затем Apply, ключи и reentrant callbacks. Добавлен Linux `silentfilm_preset_abi` с намеренно подменённым filesystem-символом. Это не запуск Resolve: сначала проверь открытие проекта, затем Save/Apply/Refresh.

После успешных тестов закрой Resolve и обнови bundle:

```bash
sudo cp -a build-cuda/ofx/ALEXZSilentFilm.ofx.bundle /usr/OFX/Plugins/
```

В Resolve проверь:

1. Defects: сохрани настройки с русским именем, поменяй их, примени пресет — возвращаются Blend/Strength/материал/Pattern/Damage Model/Irregularity/seed/размеры/параметры времени. Сравни кадр и проверь Undo.
2. На новом экземпляре и в другом проекте Refresh показывает тот же вариант. Повторный Save с тем же именем обновляет один файл; сохранение под новым именем создаёт второй вариант.
3. Negative/Print/Projector/Camera Optics: сохраняются и возвращаются их собственные настройки, варианты Defects не появляются в чужих списках.
4. Save проекта/переоткрытие: настройки ноды не меняются сами. На ноде с ключами Apply сообщает отказ, ключи и значения остаются прежними.
5. Crank Exposure: Apply меняет Blend, сохраняя текущие Exposure Map и Frame Offset. Проверь Color и Fusion, отсутствие красных нод/зависаний и доступность Saved Presets и выбора файла.

При проблеме пришли Preset Status и строки `[ALEXZSilentFilmOFX] user preset`/`preset list` из Console/лога Resolve. Файл можно выбрать через Preset File либо применить библиотечный вариант по имени.

В0.34 lifecycle-тест также проверяет выбор имени/пути без применения, появление новых вариантов и нейтрализацию удалённых без propReset. Пользователь должен отдельно подтвердить UI реального Resolve; standalone host double его не заменяет.
