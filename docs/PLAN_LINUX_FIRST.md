# План Linux-first реализации SilentFilm для Resolve

## Границы

- Новый независимый C++17/OpenFX-проект. Существующий ComfyUI SilentFilm и его workflows не меняются.
- Первый хост — установленный Resolve Studio 20.2 под Linux x86_64. Windows/macOS добавляются после подтверждения базового контракта.
- Python-версия служит эталоном математики. В будущем общий native core можно подключить к Python отдельной задачей.
- Не обещаем автоматическое изменение монтажной длительности клипа обычным OFX-фильтром. Каденс при постоянной длительности и retime — разные режимы, требующие проверки возможностей Resolve.

## 1. Проверить контракт хоста — исходники прототипа подготовлены

Подготовлен Host Probe: регистрация, UI, CPU float RGBA, identity, временные запросы и отмена. Пользователь подтвердил Release-сборку на Linux системным GCC 13.3 (`/usr/bin/c++`), создание `.ofx.bundle` и CTest 1/1 PASS. Взаимодействие с Resolve ещё не проверено; успешная сборка сама по себе не подтверждает загрузку плагина и temporal access.

Первый запуск Resolve обнаружил библиотеку, но отклонил `Describe`: `plugin description: 3` (`kOfxStatErrUnknown`), затем `No context is available`. По примеру SDK текстовое описание, дополнительные labels и hints сделаны необязательными: отсутствие свойства не отменяет регистрацию, остальные ошибки не игнорируются. После исправления пользователь подтвердил появление эффекта, его подключение и работу в Resolve. Подробные результаты temporal access, границ, отмены и экспорта пока не представлены.

Последующим сообщением пользователь подтвердил temporal mix, изменение offset, повторяемость после перемотки и обработку первого/последнего кадра. Отдельное подтверждение отмены, короткого экспорта и проверки обоих контекстов Color/Fusion пока не представлено.

Подтвердить:

1. Экспорт entry points и загрузку bundle в Resolve.
2. Нейтральность, обработку RGB/alpha, анимацию параметров и несколько экземпляров.
3. Запрос соседних кадров в Color и Fusion, включая края клипа.
4. Одинаковый результат при повторном запросе, перемотке, смене proxy и порядке кадров.
5. Отмену, отсутствие удержания host images после action и корректный короткий экспорт.

Это диагностический плагин с отдельным ID. Его временные параметры не становятся контрактом будущих художественных эффектов.

## 2. Добавить Linux CUDA — исходники подготовлены, проверки ожидаются

Сначала изучить negotiated GPU properties и host stream на установленном Resolve. Добавить CUDA backend к тому же gain/temporal probe, сохранить CPU как эталон. CPU-указатели и CUDA-указатели не смешивать; включать поддержку GPU в descriptor только после реализации соответствующего render path. Учесть lifetime входных кадров и асинхронного stream.

Сравнить CPU/CUDA на коротком клипе. Выяснить, какие temporal-запросы и буферы доступны на GPU в Color и Fusion. Только после этой проверки выбирать реализацию temporal optical flow.

Подготовлен CUDA kernel с общей CPU/CUDA пиксельной функцией, signed stride и раздельными bounds кадров. OpenFX adapter читает `CudaEnabled` и `CudaStream`, не разыменовывает GPU-указатели на CPU, не создаёт собственный device/context и не использует глобальную синхронизацию. Сборка включается через `SILENTFILM_ENABLE_CUDA=ON`, CUDA runtime статический. Добавлен тест сравнения CPU/CUDA на малых буферах с padding, изменёнными origins, отрицательным stride, HDR/alpha и двумя режимами stream. Код не собирался и не запускался агентом. Команды и сценарий — в `CUDA_VALIDATION.md`.

Пользователь подтвердил успешную Release-сборку GCC 13.3 / NVIDIA CUDA 13.0.88 (архитектура 86), создание bundle и CTest 2/2 PASS; GPU parity test выполнен, не пропущен. Следующий шаг — установка CUDA bundle и подтверждение `CUDA` в трассировке render Resolve, temporal access, отмены и короткого экспорта. Агент сборку и тесты не запускал.

При чтении текущего `~/.local/share/DaVinciResolve/logs/ResolveDebug.txt` обнаружены CUDA render-запросы с mix=1, соседями ±1/±4 и произвольным порядком времени. Resolve перенаправляет stderr в этот файл, поэтому стартовый терминал трассу не показывал. Выбор GPU backend подтверждён; отдельное подтверждение качества просмотра/экспорта, отмены и обоих контекстов остаётся за пользователем.

## 3. Перенести нейтральную Negative → Print пару — исходники 0.3 подготовлены

- Перенести калиброванные кривые из Python в независимое ядро.
- Зафиксировать цветовой контракт входа и выхода. Не трактовать DaVinci Intermediate/Log как sRGB.
- Сначала согласованный SDR-процесс с явно настроенными CST; Log/HDR добавлять отдельно.
- Проверить нейтральную пару, детали в светах/тенях, float range, premultiplication и положительное контрольное превью негатива.
- Не вводить скрытый автоконтраст и не менять художественные параметры ради отличий API хоста.

Подготовлен `include/silentfilm/sensitometry.hpp` с общей CPU/CUDA реализацией: log-exposure → оптическая плотность → пропускание негативной эмульсии → экспонирование/проявка позитивной эмульсии → фиксированная калибровка просмотра. Добавлены экспозиция, контраст, компрессия теней/светов, вуаль, Linear/sRGB/Gamma 2.4 и контрольный позитив Negative. SDR-ограничение 0–1 задано явно; входное и выходное кодирование согласует пользователь. Альфа обрабатывается по host premultiplication properties, без использования её для метаданных.

В общем bundle зарегистрированы самостоятельные `com.alexz.silentfilm.negative` и `com.alexz.silentfilm.print`; Host Probe сохранён. Для новых эффектов не запрашиваются соседние кадры и не объявляется identity при нейтральных настройках: каждый этап физически изменяет представление изображения. CPU-тесты проверяют серую шкалу, double-эталон плотностей, направления EV, premultiplication и контрольный позитив; CUDA parity дополнена обоими этапами и их настройками. Новые исходники не собирались и не запускались агентом; пользовательские результаты ожидаются.

Пользователь последующим сообщением подтвердил, что все тесты 0.3 прошли; полный лог последнего прогона не присылался. Следующий шаг — ручная проверка пары в Resolve по `NEGATIVE_PRINT.md`. Состояние для отдельного диалога находится в `SESSION_HANDOFF.md`, карта Python-эталона — в `REFERENCE_MAP.md`.

## 4. Перенести оптику, зерно и самостоятельные дефекты

Оптика Camera, grain, halation Negative/Print, glow Projector и отдельные повреждения. Размеры эффектов задавать относительно полного кадра, учитывать render scale/proxy. Для blur определить области зависимости и halo до включения tiled rendering.

Модель случайности должна быть версионируемой и независимой от устройства, порядка render и числа экземпляров. Побитовая эквивалентность GPU между платформами не обещается, но рисунок дефектов и временная привязка должны воспроизводиться.

## 5. Перенести Camera/Cadence

Общая воспроизводимая модель по seed, параметрам и опорному времени возвращает индекс виртуального кадра, фазу ручки, границы экспозиции и движение камеры для любого запрошенного момента. Допустима небольшая таблица экспозиций; не нужно держать весь видеобатч.

- Экспозиция и движение камеры используют одну модель ручки.
- Зерно/дефекты плёнки привязаны к виртуальным кадрам; проектор — к времени показа.
- Сначала простое экспозиционное смешивание, затем motion compensation/optical flow.
- Проверить границы клипа, trimming, Resolve retime и source-time mapping экспериментально.
- `film_json` не переносится как отдельный универсальный порт OpenFX. Общую конфигурацию этапов задавать через версионируемый профиль и, при необходимости, Fusion controller.

## 6. Подготовить пользовательский пакет

Отдельные эффекты Camera, Negative, Print, Projector и дефекты с общим core. Затем можно добавить объединённый эффект и Fusion-шаблон. Стабильные ID и формат параметров фиксируются после проверки прототипа; ID Host Probe не переиспользуется.

## 7. Добавить другие платформы

- Windows x64: нативная сборка, bundle, CUDA/OpenCL при поддержке хоста.
- macOS: поддерживаемые архитектуры, упаковка и Metal.
- Общая математика и контрольные данные; отдельные GPU wrappers и матрица проверок.

OpenCL и Metal не подменяются CUDA. Плагин не должен требовать установленного Python/Conda. Декодирование, медиакэш и запись финального видео выполняет Resolve.

## Прочитанные первичные источники

- `/opt/resolve/Developer/OpenFX/README.txt` — структура SDK и bundle, CPU/CUDA/OpenCL/Metal примеры.
- `TemporalBlurPlugin/TemporalBlurPlugin.cpp`: `getFramesNeeded`, `setupAndProcess` — временной диапазон и получение изображений.
- `GainPlugin/GainPlugin.cpp`: `describe`, CPU/GPU processing — объявление возможностей.
- `OpenFX-1.4/include/ofxImageEffect.h` — clip lifetime, frame range, render window, row stride, temporal access, identity.
- `OpenFX-1.4/include/ofxCore.h`, `ofxProperty.h`, `ofxParam.h` — ABI, suites и параметры.
- `OpenFX-1.4/include/ofxGPURender.h`: `CudaRenderSupported`, `CudaEnabled`, `CudaStreamSupported`, `CudaStream` — согласование GPU-буферов и асинхронного выполнения.
- Python-эталон: `ComfyUI_ALEXZ_SilentFilm/utils/film_sensitometry.py`, `film_optics.py`, `film_defects.py`, `nodes/video_silent_film_cadence.py`.
