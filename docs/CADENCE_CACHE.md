✅ **2026-11-13 — исправлена очистка Exposure via OFX.** Ранее такие задания целиком исключались из кандидатов из-за защиты карты. Теперь при отсутствии использования удаляется вся папка результата: видео, промежуточные файлы, `exposure.sfexposure`, индивидуальный `crank_exposure.drx` и служебные данные. Карта уже хранится рядом с результатом, а не в общих presets; там остаётся только эталонный DRX. Удаление с таймлайна само по себе не очищает Media Pool/диск: нужно запустить Clean Project/Timeline Cache и подтвердить список. Пользователь подтвердил работу очистки 2026-11-13. Агент проверки не запускал и реальные данные не удалял.

Cadence работает с выделенным видеоклипом текущего таймлайна. **Selected Timeline Clip** — информационная строка с проектом, таймлайном, именем клипа, дорожкой и диапазоном. Она обновляется в простое примерно раз в пять секунд и при открытии окна из меню Resolve. Перед **Calculate** выделение читается повторно. Выбор Media Pool или произвольного входного файла в приложении удалён.

**Output Folder** задаёт общий корень хранения. Поле запоминается между запусками и входит в именованные пресеты. **Browse…** выбирает папку. Внутри используется структура:

```text
Output Folder/
  Название проекта_<короткий ID проекта>/
    .silentfilm-project.json
    Название клипа_cadence_<уникальный ID>/
      .silentfilm-cache.json
      app_context.json
      request.ini
      status.ini
      result.ini
      Название клипа_cadence.mov
      ...
```

Для TIFF внутри папки генерации находится `frames/`. Отдельная папка создаётся для каждого расчёта, прежние результаты не перезаписываются. Имена очищаются от непереносимых символов с сохранением Unicode. ID проекта отделяет одноимённые проекты; при переименовании проекта в том же корне находится прежняя папка по полному ID из паспорта. Пресет хранит только корень, имя проекта и клипа каждый раз берётся из Resolve. Паспорт генерации содержит ID проекта, исходного таймлайна и самой генерации.

## Две области очистки

- **Clean Timeline Cache** — рассматривает генерации, созданные для текущего таймлайна.
- **Clean Project Cache** — рассматривает все генерации текущего проекта в выбранной Output Folder.

В обоих режимах проверяются **все таймлайны проекта**, а не только открытый: клип, используемый на другом таймлайне, сохраняется. Проверяются и видео-, и аудиодорожки. Ссылка на отдельный TIFF-кадр или последовательность сохраняет всю папку генерации. Отключённые дорожки и клипы также считаются использованием.

Дополнительно рекурсивно проверяется Media Pool. Если `Usage` соответствующего файла ненулевой или не удалось однозначно прочитать это число, результат не удаляется. Для удаления подходят собственные генерации с конечным native-статусом `complete`, `error` или `cancelled`. Активные, ещё не запущенные native-задания и папки без паспортов не удаляются. Старые результаты в плоской структуре автоматически не переносятся и не удаляются.

Перед удалением приложение показывает проект, область, список папок и общий объём. После подтверждения повторно проверяются проект, текущий таймлайн для режима Timeline, состояние и использование файлов. Удаляются только подтверждённые генерации. Сначала удаляются соответствующие неиспользуемые записи Media Pool; если Resolve отказал, файлы сохраняются. Затем удаляется папка генерации вместе с промежуточными файлами и служебными данными. Очистка не удаляет сами таймлайны, монтажные клипы или исходные видео. Undo монтажа не восстанавливает физически удалённые результаты — об этом написано в подтверждении.

## Границы изоляции

Служебный `SilentFilm backup — <timestamp>` создаётся перед изменением монтажа. После успешной вставки и проверки позиций он удаляется; при ошибке остаётся для восстановления. Если Resolve отказал в удалении копии, импорт всё равно считается завершённым, а сообщение сообщает имя оставшегося backup. Такие копии являются настоящими таймлайнами и их ссылки учитываются очисткой. Уже накопленные backup автоматически не удаляются: они могли понадобиться для восстановления. После проверки основного монтажа ненужные служебные копии можно удалить вручную из Media Pool и повторить очистку кэша.

Очистка рассматривает только папки с паспортами **текущего проекта**. Генерация того же исходника в другом проекте имеет собственную папку и сохраняется. Импорт результата средствами Cadence в другой проект блокируется существующей проверкой project ID.

Если вручную импортировать один и тот же физический результат из папки проекта A в проект B, принадлежность папки не меняется. Использование файла в закрытом проекте B этот SDK-запрос не проверяет; для такого ручного обмена нужна самостоятельная копия вне управляемого кэша. Аналогично не анализируются произвольные пути, записанные внутри Fusion Loader, внешних скриптов или OFX. Для обычного импорта результатов Cadence на таймлайн используются файловые ссылки MediaPoolItem.

Выбор другой Output Folder ограничивает очистку новым корнем. Для очистки прежнего хранилища выбери его снова. Сборки, тесты и работа очистки в Resolve агентом не запускались; реальные данные не удалялись.

Подготовлены проверки, запускаемые пользователем:

```bash
PYTHONDONTWRITEBYTECODE=1 /usr/bin/python3 tests/cadence_cache_tests.py
PYTHONDONTWRITEBYTECODE=1 /usr/bin/python3 tests/cadence_preferences_tests.py
PYTHONDONTWRITEBYTECODE=1 /usr/bin/python3 tests/cadence_bridge_tests.py
```

Для Python-изменений достаточно переоткрыть `SilentFilm_Cadence_App`. Новый CTest `silentfilm_cadence_cache` появится после повторной конфигурации CMake; для применения интерфейса rebuild helper не нужен.
