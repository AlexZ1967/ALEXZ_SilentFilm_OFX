# ALEXZ SilentFilm для Windows: пошаговый гайд

Эта инструкция рассчитана на человека, который пользуется DaVinci Resolve, но раньше не собирал программы. Писать код не нужно: понадобится установить несколько инструментов и по очереди вставлять готовые команды.

**Статус на 18 ноября 2026 года:** Windows-сценарии подготовлены, но первая сборка и запуск в Windows ещё не подтверждены. Поэтому инструкция содержит контрольные точки: если шаг закончился ошибкой, сначала разбираемся с ней, затем продолжаем. Готовая проверенная Windows-версия пока не объявлена.

## Как выбрать свой маршрут

| Что у вас есть | Что делать |
| --- | --- |
| Вам передали готовый Windows ZIP с плагином | Разделы 1–3, затем раздел 12. Компилятор и CMake не нужны |
| Есть только исходники проекта | Разделы 1–11, затем установка и проверка из разделов 12–13 |
| Нужно приложение Cadence с отдельным окном | Перейти к разделу 16: отдельная сборка с `-Cadence` и установка GTK |

**OFX-плагин** — это эффекты Camera Optics, Negative, Print, Defects, Projector и другие внутри Resolve. **Cadence App** — отдельная программа, которая пересчитывает длительность клипа. У них разная установка.

## 1. Проверить компьютер

Начальная конфигурация этого гайда:

- Windows 11, **64-разрядная, процессор x64**;
- установленный **DaVinci Resolve Studio**;
- доступ в Интернет для скачивания инструментов;
- права администратора для установщиков и копирования OFX;
- свободное место на диске для Visual Studio, CUDA и файлов сборки. Объём показывают установщики; суммарно могут потребоваться десятки гигабайт.

### Как посмотреть версию Windows

Откройте **Пуск → Параметры → Система → О системе**. Посмотрите «Тип системы». Для этого гайда нужен вариант с **64-разрядной системой и процессором x64**. Windows на ARM этим этапом не охватывается.

### Как посмотреть видеокарту

Нажмите правой кнопкой на **Пуск → Диспетчер устройств → Видеоадаптеры**. Запишите полное название карты.

- Если есть **NVIDIA**, после CPU-проверки можно переходить к CUDA-сборке.
- Если NVIDIA нет, используйте CPU-вариант. Он считает на процессоре; CUDA-шаги пропускаются.

CPU-вариант также полезен на NVIDIA: сначала он позволит проверить обычную сборку, затем отдельно подключить GPU.

### Проверить Resolve

Откройте Resolve, убедитесь, что он запускается и воспроизводит обычный клип. Версию можно посмотреть в **Help → About DaVinci Resolve**. Запишите её. Перед установкой плагина Resolve потребуется закрыть.

## 2. Подготовить рабочую папку

В Проводнике откройте диск `C:` и создайте папку **work**. В дальнейшем используем такие пути:

```text
C:\work\ALEXZ_SilentFilm_OFX   — исходники и результаты сборки
C:\work\vcpkg                 — инструмент установки библиотеки FFTW
C:\work\SilentFilm-ready      — распакованный готовый плагин, если он вам передан
```

Для первой сборки лучше придерживаться именно этих путей. Не размещайте проект в Program Files или синхронизируемой папке OneDrive. Простые пути уменьшают число настроек, которые нужно менять в командах.

В Проводнике включите показ расширений файлов: **Вид → Показать → Расширения имён файлов**. Так будет проще отличать `.zip`, `.ps1` и `.ofx`.

## 3. Установить Visual C++ Runtime

Он нужен и для готового плагина, и для собственной сборки.

1. Откройте [официальную страницу Microsoft Visual C++ Redistributable](https://learn.microsoft.com/en-us/cpp/windows/latest-supported-vc-redist?view=msvc-170).
2. В разделе актуальной версии **v14** скачайте установщик **x64**.
3. Запустите скачанный `.exe`.
4. Нажмите **Install / Установить**. Если подходящая версия уже есть, установщик может предложить восстановление либо сообщить, что установка не требуется.
5. Если предложена перезагрузка, выполните её.

Runtime должен быть не старее инструментов, которыми собран плагин. Microsoft описывает это требование на той же странице.

**Если у вас готовый Windows ZIP:** переходите к разделу 12. Скачивание исходников, Visual Studio, FFTW и CUDA Toolkit для установки такого ZIP не требуется. Для GPU-варианта нужен совместимый NVIDIA driver, а runtime DLL должны входить в переданный bundle.

## 4. Установить инструменты сборки Visual Studio 2022

Visual Studio содержит **компилятор**: он превращает исходники в готовый плагин. Сам редактор Visual Studio открывать для сборки не понадобится.

### 4.1. Скачать нужный установщик

Откройте [официальную страницу предыдущих версий Visual Studio](https://visualstudio.microsoft.com/vs/older-downloads/) и найдите **Visual Studio 2022**. Для нашей сборки подходят **Build Tools 2022** либо установленная Visual Studio 2022 с C++.

Нужен именно выпуск **2022**. Текущий установщик другой основной версии не является заменой для подготовленного сценария.

### 4.2. Выбрать компоненты

1. Запустите установщик. Откроется **Visual Studio Installer**.
2. На вкладке **Workloads / Рабочие нагрузки** отметьте **Desktop development with C++ / Разработка классических приложений на C++**.
3. Откройте **Individual components / Отдельные компоненты**.
4. В поиске компонентов введите **14.39**.
5. Отметьте **MSVC v143 — VS 2022 C++ x64/x86 build tools (v14.39–17.9)**. Название может немного отличаться из-за языка установщика.
6. Убедитесь, что выбран **Windows SDK**. Как правило, workload предлагает его автоматически.
7. Нажмите **Install / Установить** и дождитесь завершения.

Наличие только «последнего v143» недостаточно: сценарий первой сборки выбирает **14.39** явно. Можно оставить установленными и новый toolset, и 14.39.

Если Visual Studio 2022 уже установлена: найдите **Visual Studio Installer** через «Пуск», напротив версии 2022 нажмите **Modify / Изменить** и добавьте компоненты по этому списку. [Описание изменения компонентов у Microsoft](https://learn.microsoft.com/en-us/visualstudio/install/modify-visual-studio?view=vs-2022).

**Результат шага:** установлена Visual Studio/Build Tools 2022, C++ workload, toolset 14.39 и Windows SDK. Если компонента 14.39 в списке нет, не выбирайте случайную замену: запишите версию установщика и пришлите названия доступных компонентов.

## 5. Установить Git и CMake

### 5.1. Git

Git скачает исходники с GitHub.

1. Откройте [Git for Windows](https://git-scm.com/download/win).
2. Скачайте установщик для x64 и запустите его.
3. Для обычных вопросов можно оставить предложенные настройки.
4. На странице выбора PATH оставьте вариант **Git from the command line and also from 3rd-party software**: Git будет доступен из PowerShell.
5. Дождитесь окончания установки.

### 5.2. CMake

CMake управляет процессом сборки. Нужна версия **4.1 или новее**.

1. Откройте [официальную страницу CMake](https://cmake.org/download/).
2. Найдите раздел стабильного выпуска **Latest Release**, не Release Candidate.
3. Скачайте **Windows x64 Installer**, файл `.msi`.
4. Запустите установщик.
5. Если предлагается выбор PATH, отметьте **Add CMake to the system PATH** для текущего пользователя либо всех пользователей.
6. Завершите установку.

**После установки закройте ранее открытые окна терминала.** Новое окно получит обновлённые пути к Git и CMake.

## 6. Открыть окно для команд

Нажмите **Пуск**, наберите **Developer PowerShell for VS 2022** и откройте найденное приложение. Для сборки запуск от администратора обычно не нужен.

Это окно, в которое мы будем вставлять команды. Не вставляйте их в Console внутри Resolve, адресную строку браузера или Git Bash.

Правила работы:

1. Скопируйте команду или целый блок между рамками.
2. Вставьте в PowerShell и нажмите **Enter**. Предупреждение о вставке нескольких строк ожидаемо, если вы копируете блок из этого гайда.
3. Дождитесь окончания: внизу снова появится приглашение, обычно начинающееся с `PS`.
4. Не вводите следующую команду, пока предыдущая работает.
5. Слово `powershell` над блоком — подпись языка, копировать его не нужно. Символы тройных кавычек вокруг блока также не копируются.

Проверьте инструменты по очереди:

```powershell
git --version
```

Ожидается строка с версией Git.

```powershell
cmake --version
```

Ожидается версия CMake **4.1 или выше**.

```powershell
cl
```

Ожидается информация Microsoft C/C++ Compiler. После неё может быть сообщение о том, что не задан исходный файл: **для этой команды это нормально**, мы только проверяем наличие компилятора. Номер здесь может относиться к toolset по умолчанию; наша сборка отдельно выбирает установленный 14.39.

Если команда «не распознана», вернитесь к установке соответствующего инструмента и снова откройте Developer PowerShell. Не продолжайте сборку с отсутствующими инструментами.

## 7. Скачать исходники плагина

В том же Developer PowerShell:

```powershell
New-Item -ItemType Directory -Path C:\work -Force
Set-Location C:\work
git clone https://github.com/AlexZ1967/ALEXZ_SilentFilm_OFX.git
Set-Location C:\work\ALEXZ_SilentFilm_OFX
```

Git скачает папку проекта. После окончания убедитесь, что Windows-сценарий есть:

```powershell
Test-Path .\scripts\windows\Build-Windows.ps1
```

**Ожидается `True`.**

Если получили `False`, у вас ревизия без Windows-файлов. На момент подготовки этого гайда изменения находятся локально и ещё требуют отдельной публикации. До появления этих файлов в скачанном проекте следующие команды сборки выполнить нельзя.

Если `git clone` пишет, что папка уже существует, не удаляйте её вслепую. Для ранее скачанного проекта без собственных изменений можно обновить исходники:

```powershell
git -C C:\work\ALEXZ_SilentFilm_OFX pull --ff-only
```

Если Git сообщает о конфликте или ваших изменениях, остановитесь и сохраните сообщение. Команды сброса и удаления для этого не нужны.

## 8. Подготовить библиотеку FFTW

FFTW нужна для оптических эффектов. Скачивать отдельные DLL вручную не требуется: библиотеку подготовит **vcpkg**, менеджер зависимостей C++.

Каждую следующую команду запускайте отдельно и дождитесь завершения:

```powershell
git clone https://github.com/microsoft/vcpkg.git C:\work\vcpkg
```

```powershell
git -C C:\work\vcpkg checkout de36db04550a8625e3154b1a758c60035901f244
```

Эта длинная строка фиксирует одну версию vcpkg. Сообщение Git про **detached HEAD** в данном случае нормально: мы выбрали конкретную ревизию.

```powershell
& C:\work\vcpkg\bootstrap-vcpkg.bat -disableMetrics
```

Ожидается завершение без ошибки и появление `C:\work\vcpkg\vcpkg.exe`.

```powershell
& C:\work\vcpkg\vcpkg.exe install fftw3:x64-silentfilm --overlay-triplets=C:\work\ALEXZ_SilentFilm_OFX\cmake\triplets
```

Эта команда скачивает и собирает FFTW. Первый запуск может идти заметно дольше обычной сборки плагина. Дождитесь сообщения об успешной установке пакетов.

Проверьте наличие заголовка:

```powershell
Test-Path C:\work\vcpkg\installed\x64-silentfilm\include\fftw3.h
```

**Ожидается `True`.** Если установка FFTW закончилась ошибкой, одного наличия файла недостаточно: сначала нужно устранить ошибку установки.

`x64-silentfilm` — наша подготовленная конфигурация библиотеки. Не заменяйте её на похожее `x64-windows`: команда сборки ожидает именно первый вариант.

## 9. Найти заголовки OpenFX SDK

SDK — набор файлов для разработчиков плагинов, поставляемый с Resolve. Для сборки нужны файлы **`ofxImageEffect.h` и `ofxGPURender.h` в одной папке**. Их менять или открывать в редакторе не нужно. Не выбирайте папку с самим `Resolve.exe` вместо папки заголовков.

Вставьте следующий блок в Developer PowerShell целиком. Он только ищет файлы в обычных каталогах установки Resolve:

```powershell
$resolveFolders = @(
    "$env:ProgramFiles\Blackmagic Design\DaVinci Resolve",
    "$env:ProgramData\Blackmagic Design\DaVinci Resolve"
)
$ofxHeader = Get-ChildItem -Path $resolveFolders -Filter ofxImageEffect.h -File -Recurse -ErrorAction SilentlyContinue |
    Where-Object { Test-Path (Join-Path $_.DirectoryName 'ofxGPURender.h') } |
    Select-Object -First 1
if (!$ofxHeader) { throw 'OpenFX SDK headers not found. Locate ofxImageEffect.h and ofxGPURender.h in the Resolve SDK.' }
$ofxInclude = $ofxHeader.DirectoryName
Write-Host "OpenFX headers: $ofxInclude"
```

**Ожидается строка `OpenFX headers:` с реальным путём.** Переменная `$ofxInclude` запоминает его в текущем окне — она понадобится при сборке.

Если файлы не найдены:

1. Откройте в Проводнике папку вашей установки Resolve.
2. Найдите каталог **Developer → OpenFX**. Он также может находиться в `C:\ProgramData\Blackmagic Design\DaVinci Resolve\Support\Developer`.
3. Если SDK упакован в архив, распакуйте его отдельно, например в `C:\work\ofx-sdk`.
4. Через поиск Проводника найдите `ofxImageEffect.h`. Откройте содержащую его папку и убедитесь, что рядом есть `ofxGPURender.h`.
5. Щёлкните адресную строку Проводника и скопируйте полный путь.
6. Введите в PowerShell, подставив **свой настоящий путь**:

```powershell
$ofxInclude = 'C:\work\ofx-sdk\OpenFX-1.4\include'
```

Путь выше — пример, не универсальное расположение SDK. Если файлов нет и в SDK, сообщите версию Resolve и где искали. Без них сборка не начнётся.

**Не закрывайте это окно PowerShell до следующего шага.** Если закрыли, повторите поиск или снова задайте `$ofxInclude` своим путём.

## 10. Собрать и проверить CPU-плагин

Закройте Resolve. В Developer PowerShell перейдите в проект:

```powershell
Set-Location C:\work\ALEXZ_SilentFilm_OFX
```

Разрешите запуск локальных сценариев только для этого окна:

```powershell
Set-ExecutionPolicy -Scope Process RemoteSigned
```

Если PowerShell спросит подтверждение, подтвердите изменение. После закрытия окна это разрешение перестанет действовать. Если изменение запрещено политикой организации, нужен её администратор.

Запустите сборку одной строкой:

```powershell
& .\scripts\windows\Build-Windows.ps1 -OfxIncludeDir $ofxInclude -VcpkgRoot C:\work\vcpkg
```

### Что произойдёт

Сценарий сам выполнит пять действий:

1. Проверит настройки CMake.
2. Скомпилирует плагин.
3. Запустит автоматические тесты CTest.
4. Сложит готовый плагин в отдельную папку.
5. Создаст ZIP-архив.

Во время работы будет много текста и процентов. **Предупреждение (`warning`) само по себе не всегда означает ошибку.** Решающее значение имеет завершение команды: если сценарий пишет `failed` и останавливается, следующий этап не выполнен.

### Как выглядит успех

В выводе тестов нет `Failed`, затем сценарий печатает строки **`Bundle:`** и **`Archive:`**. Готовые файлы:

```text
C:\work\ALEXZ_SilentFilm_OFX\build-windows-cpu\stage\ALEXZSilentFilm.ofx.bundle
C:\work\ALEXZ_SilentFilm_OFX\build-windows-cpu\ALEXZSilentFilm-windows-x64-cpu.zip
```

**Сборка пока ничего не устанавливает в Resolve.** Для установки переходите к разделу 12. Можно сначала проверить CPU-плагин в Resolve и только затем вернуться к GPU-сборке.

Если возникла ошибка, скопируйте её текст вместе с предшествующими строками. Не переходите к установке файла, оставшегося от прежней неуспешной сборки.

## 11. Собрать CUDA-вариант для NVIDIA

Этот раздел нужен только при наличии подходящей NVIDIA GPU. CPU-сборка должна быть пройдена раньше. Перед заменой установленного плагина закройте Resolve.

### 11.1. Установить драйвер NVIDIA

Скачайте драйвер для своей карты и Windows с [официального сайта NVIDIA](https://www.nvidia.com/drivers/). Для рабочей станции монтажа можно выбирать предлагаемый для карты Studio Driver. Выполните установку и предложенную перезагрузку.

### 11.2. Установить CUDA Toolkit

1. Откройте [CUDA Toolkit 13.0 Update 1](https://developer.nvidia.com/cuda-13-0-1-download-archive).
2. Выберите **Windows → x86_64 → версию Windows → exe (local)**, если такой вариант предлагается.
3. Скачайте и запустите установщик.
4. Установите Toolkit, включая компилятор, библиотеки и **Visual Studio Integration**. Visual Studio 2022 к этому моменту уже должна быть установлена.
5. Оставьте стандартный каталог, если нет причины его менять:

```text
C:\Program Files\NVIDIA GPU Computing Toolkit\CUDA\v13.0
```

Для первой конфигурации выбираем именно **13.0 Update 1**, а не любую последнюю CUDA. Связка с MSVC 193x / Visual Studio 2022 описана в [таблице совместимости NVIDIA](https://docs.nvidia.com/cuda/archive/13.0.1/cuda-installation-guide-microsoft-windows/index.html).

### 11.3. Проверить установку

В Developer PowerShell:

```powershell
nvidia-smi
```

Ожидается таблица с вашей видеокартой и драйвером.

```powershell
& 'C:\Program Files\NVIDIA GPU Computing Toolkit\CUDA\v13.0\bin\nvcc.exe' --version
```

Ожидается информация о компиляторе CUDA версии **13.0**. Значение `CUDA Version` в таблице `nvidia-smi` относится к возможностям драйвера; для установленного Toolkit смотрим результат `nvcc`.

### 11.4. Выбрать архитектуру видеокарты

Сборке нужно одно число — архитектура CUDA вашей GPU. Для **RTX 3090 это `86`**.

Для другой карты найдите точную модель в [официальной таблице NVIDIA](https://developer.nvidia.com/cuda-gpus). Значение **Compute Capability** запишите без точки: например, `8.6` превращается в `86`. Не выбирайте `86` просто потому, что оно встречается в примере.

Если модели в таблице нет или выбранный Toolkit её не поддерживает, нужна проверка конкретной карты. CPU-вариант остаётся отдельным способом работы.

### 11.5. Запустить GPU-сборку

В том же окне с заданной `$ofxInclude`:

```powershell
Set-Location C:\work\ALEXZ_SilentFilm_OFX
```

**Пример для RTX 3090** — для другой карты замените последнее число:

```powershell
& .\scripts\windows\Build-Windows.ps1 -OfxIncludeDir $ofxInclude -VcpkgRoot C:\work\vcpkg -Cuda -CudaRoot 'C:\Program Files\NVIDIA GPU Computing Toolkit\CUDA\v13.0' -CudaArchitectures 86
```

Сценарий снова выполнит сборку, тесты и упаковку. Результаты находятся отдельно:

```text
C:\work\ALEXZ_SilentFilm_OFX\build-windows-cuda\stage\ALEXZSilentFilm.ofx.bundle
C:\work\ALEXZ_SilentFilm_OFX\build-windows-cuda\ALEXZSilentFilm-windows-x64-cuda.zip
```

Если CUDA-тесты помечены **Skipped**, они пропущены. Это не подтверждение работы GPU, даже если остальные тесты прошли. Для приёмки CUDA нужны выполненные тесты сравнения CPU/CUDA.

## 12. Установить плагин в Resolve

Есть два равнозначных способа. Выберите один.

### Способ А: вручную через Проводник

Он подходит и для готового ZIP, и после самостоятельной сборки.

1. **Полностью закройте Resolve.** Если он ещё завершает работу, дождитесь окончания.
2. Если вам передали ZIP, щёлкните его правой кнопкой → **Извлечь всё**. Например, в `C:\work\SilentFilm-ready`.
3. Найдите папку **`ALEXZSilentFilm.ofx.bundle`**. Если собирали сами — возьмите её из папки `stage`, указанной в разделе 10 или 11.
4. Проверьте, что внутри есть:

```text
ALEXZSilentFilm.ofx.bundle
└── Contents
    └── Win64
        ├── ALEXZSilentFilm.ofx
        └── дополнительные DLL для CUDA-варианта
```

5. Откройте в другом окне Проводника:

```text
C:\Program Files\Common Files\OFX\Plugins
```

6. Если папок `OFX` и `Plugins` нет, создайте их. Windows может запросить права администратора.
7. Если там уже установлен наш bundle, сначала **переместите его в резервную папку вне `OFX\Plugins`**, например `C:\work\SilentFilm-backup`. Не оставляйте рядом переименованную копию: Resolve может сканировать её тоже.
8. Скопируйте **папку `ALEXZSilentFilm.ofx.bundle` целиком** в `Plugins` и подтвердите запрос администратора.

Правильный итоговый путь:

```text
C:\Program Files\Common Files\OFX\Plugins\ALEXZSilentFilm.ofx.bundle\Contents\Win64\ALEXZSilentFilm.ofx
```

Каталог установки соответствует [стандарту упаковки OpenFX](https://openfx.readthedocs.io/en/latest/Reference/ofxPackaging.html).

Не копируйте только один файл `.ofx`: CUDA-варианту нужны соседние DLL. CPU и CUDA — два варианта одного плагина; устанавливайте **один**, не оба одновременно.

### Способ Б: нашим сценарием

Подходит, если у вас есть исходники со сценарием установки.

1. Закройте Resolve.
2. Нажмите **Пуск**, наберите **PowerShell**, нажмите правой кнопкой → **Запуск от имени администратора**.
3. Подтвердите запрос Windows.
4. В новом окне выполните:

```powershell
Set-ExecutionPolicy -Scope Process RemoteSigned
Set-Location C:\work\ALEXZ_SilentFilm_OFX
```

Для **CPU**:

```powershell
& .\scripts\windows\Install-OFX.ps1 -Bundle .\build-windows-cpu\stage\ALEXZSilentFilm.ofx.bundle
```

Для **CUDA** — вместо CPU-команды:

```powershell
& .\scripts\windows\Install-OFX.ps1 -Bundle .\build-windows-cuda\stage\ALEXZSilentFilm.ofx.bundle
```

Ожидается строка **`Installed:`** с каталогом назначения. Если старая версия была установлена, сценарий напечатает также **`Previous bundle:`** — путь резервной копии. Копия хранится вне сканируемой папки.

Если устанавливаете переданный ZIP, в `-Bundle` можно указать полный путь к распакованному `ALEXZSilentFilm.ofx.bundle` в одинарных кавычках.

## 13. Найти и настроить эффекты в Resolve

1. Запустите Resolve после копирования bundle.
2. Создайте **отдельный тестовый проект** и добавьте короткий обычный клип.
3. Перейдите на страницу **Color**.
4. Выделите ноду цветокоррекции.
5. Откройте панель **Effects / Open FX**. Название и расположение кнопки зависят от версии Resolve.
6. В поиске введите **SilentFilm**.
7. Перетащите нужный эффект на выбранную ноду.
8. Откройте настройки эффекта и измените один хорошо заметный параметр.

Для CUDA-варианта откройте **Preferences → System → Memory and GPU**, выберите **CUDA** и нужную NVIDIA GPU. Сохраните настройки и перезапустите Resolve, если он попросит.

### Простая первая проверка

Не добавляйте сразу всю цепочку. Сначала проверьте эффекты по одному:

| Эффект | Что попробовать | Что должно быть видно |
| --- | --- | --- |
| Camera Optics | Увеличить общий расфокус, затем виньетку | Размытие, затем затемнение краёв |
| Negative → Print | Поставить два эффекта на последовательные ноды | Работа плёночной цепочки; оценивать итог после Print |
| Defects | Добавить пыль, менять Blend от 0 до 1 | Постепенное появление дефектов |
| Projector | Добавить мерцание/дрожание, запустить воспроизведение | Изменение яркости и положения во времени |

Для сравнения вариантов CPU/CUDA используйте один исходный кадр и одинаковые параметры. После установки другого bundle Resolve нужно закрыть и запустить снова.

**Важно про цвет:** в нашей цепочке должны быть согласованы Input Transfer/Output Transfer и преобразования Resolve. Несогласованные sRGB/Linear Rec.709 ранее давали неверное впечатление о работе Blend. Для первого теста используйте простой SDR Rec.709-проект и согласованные настройки нод. Подробности — [COLOR_PIPELINE.md](COLOR_PIPELINE.md).

Crank Exposure отдельно требует файла **Exposure Map** из подготовленного каденса. Он не создаёт карту сам. После переноса клипа с Linux назначьте существующий Windows-путь карты.

## 14. Сохранить свой пресет

В ноде нашего эффекта найдите группу **My Presets**:

1. Настройте эффект.
2. Введите имя в **Preset Name**, например `Моя оптика`.
3. Нажмите **Save Preset**.
4. Если нужно, нажмите **Refresh**.
5. Выберите имя в **Saved Presets**.
6. Нажмите **Apply Preset** для применения.

Выбор имени и применение — отдельные действия. Если имя уже существует, сохранение может заменить его содержимое.

Файлы OFX-пресетов находятся в пользовательской папке:

```text
%LOCALAPPDATA%\ALEXZSilentFilm\ofx-presets
```

Чтобы открыть её: нажмите **Win+R**, вставьте этот путь и нажмите Enter. До первого успешного сохранения папка может отсутствовать.

Для первой Windows-проверки отдельно проверьте русское имя, возврат к заводским настройкам, применение своего пресета, сохранение и повторное открытие проекта. Детали — [OFX_USER_PRESETS.md](OFX_USER_PRESETS.md).

## 15. Если что-то не получилось

| Сообщение или ситуация | Что сделать |
| --- | --- |
| `git` или `cmake` не распознаны | Проверить установку/PATH, закрыть терминал и открыть новый Developer PowerShell |
| `cl` не распознан | Открыть именно Developer PowerShell for VS 2022; проверить C++ workload |
| Не найден toolset `14.39` | Visual Studio Installer → Modify → Individual components → добавить 14.39 |
| `MSB4019`, не найден `Microsoft.VCRedistVersion.default.props` | Visual Studio Installer → Build Tools2022 → More/Дополнительно → Repair/Восстановить; затем проверить компонент14.39 и повторить сборку в новом Developer PowerShell. Не копировать .props между toolset вручную. |
| `Build-Windows.ps1` не найден | Перейти в папку проекта; проверить наличие Windows-файлов в скачанной ревизии |
| Запуск сценариев запрещён | В этом окне выполнить `Set-ExecutionPolicy -Scope Process RemoteSigned`; при политике организации обратиться к администратору |
| Скачанный сценарий требует подписи | Для доверенного ZIP открыть его «Свойства», использовать «Разблокировать», если пункт есть, затем распаковать заново; не отключать защиту всего компьютера |
| Не найден OpenFX SDK | Повторить раздел 9; нужны оба `.h` в выбранной папке |
| Не найдена FFTW | Завершить установку `fftw3:x64-silentfilm`; проверить каталог `installed\x64-silentfilm` |
| `nvcc.exe` не найден | Проверить установленную версию CUDA и путь `v13.0\bin` |
| CUDA сообщает неподдерживаемый компилятор/архитектуру | Проверить 14.39 и число архитектуры своей карты; не добавлять флаги принудительного обхода ошибки |
| CUDA-тесты `Skipped` | GPU-проверка не состоялась; сохранить вывод тестов и данные драйвера/карты |
| `Close DaVinci Resolve before installing` | Resolve ещё работает; дождаться завершения, проверить Диспетчер задач |
| Нет прав на установку | Для сценария установки открыть PowerShell от администратора либо подтвердить запрос Проводника |
| Эффект не появился | Проверить точную структуру папок, отсутствие лишней вложенной папки bundle, x64 Runtime; перезапустить Resolve |
| Ошибка загрузки DLL | Проверить, что скопирован весь bundle с DLL выбранной CUDA-сборки; не подставлять случайные DLL |
| Плагин грузится, но результат неверный | Проверить согласованность цветовых пространств и параметры; сравнить один эффект с исходником |

### Как передать полезный лог

Не присылайте только последнюю строку `failed`: причина часто находится выше.

Для сохранения следующей попытки сборки откройте Developer PowerShell, перейдите в проект и включите запись:

```powershell
Set-Location C:\work\ALEXZ_SilentFilm_OFX
Start-Transcript -Path .\windows-build-session.txt
```

Повторите команду, на которой возникла ошибка. Затем:

```powershell
Stop-Transcript
```

Файл **`windows-build-session.txt`** появится в папке проекта. Приложите его вместе с названием GPU, версиями Windows и Resolve. В логе могут быть ваши локальные пути — просмотрите его перед отправкой.

Если ошибка только в Resolve, в его меню **Help** найдите **Create Diagnostics Log on Desktop** или аналогичный пункт создания диагностического журнала. Приложите полученный архив и опишите, после какого действия произошла ошибка.

### Как вернуть прежнюю версию

1. Закройте Resolve.
2. Переместите установленный `ALEXZSilentFilm.ofx.bundle` из `OFX\Plugins` в отдельную папку.
3. Верните сохранённый старый bundle с именем **`ALEXZSilentFilm.ofx.bundle`** в `OFX\Plugins`.
4. Запустите Resolve.

При установке сценарием резервные копии находятся в `%LOCALAPPDATA%\ALEXZSilentFilm\ofx-backups`. Там имя копии техническое: при восстановлении её нужно назвать `ALEXZSilentFilm.ofx.bundle`.

## 16. Что с отдельным приложением Cadence

Для Cadence подготовлен полный Windows-путь: собственный native helper с FFmpeg/OpenCV, существующий CPU/CUDA расчёт и запрос кадров с обработками из Resolve через локальный транспорт. Он ещё требует проверки на настоящем Windows-компьютере.

**Обычная OFX-сборка без `-Cadence` не создаёт приложение.** Чтобы получить его, дополнительно установить GTK/Pango, подготовить медиабиблиотеки и выполнить сборку с `-Cadence`. Затем запускать `Start-Cadence.cmd` или установить команду в меню Resolve. Все шаги и команды — [WINDOWS_CADENCE_APP.md](WINDOWS_CADENCE_APP.md).

Для одного OFX GTK/Pango не нужны. Для приложения требуется Resolve Studio21.1+ с встроенным ResolvePython. Первая проверка — Raw/Bake/Add Above, затем Processed с эффектами и остальные сценарии.
