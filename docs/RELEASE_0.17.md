# Итог этапа 0.17 — 2026-11-12

✅ **2026-11-12 — оформлена версия 0.17.0.** Сохранены изменения после 0.16: ускорение входного тракта и GPU sampler, исправления приложения и последовательная очередь выбранных монтажных клипов. Статус проверок указан отдельно от готовности кода.

## Что изменилось

- Несколько выделенных видеоэкземпляров обрабатываются последовательно по позиции на таймлайне. Для каждого сохраняются собственные In/Out; настройки общие. Связанное аудио не добавляется в очередь. Автоимпорт каждого результата завершается до запуска следующего клипа.
- Режимы Replace/Add Above сохраняют позиции остального монтажа. Отключённая свободная верхняя дорожка тоже используется; её видимость не меняется. Результаты получают имя с `_cadence`, отчёт очереди — `batch_reports/batch_*.json`.
- Ошибка или отмена останавливает остаток очереди, готовые результаты сохраняются. При закрытии окна текущий native-процесс может продолжиться отдельно; следующие клипы не запускаются. Возобновление всей очереди из отчёта пока не реализовано.
- Use Raw Source читает исходный файл напрямую нативным декодером. Raw/Processed используют одинаковые число входных кадров и FPS таймлайна; переключатель отключает обработки, сохраняя монтажную временную сетку.
- Обработанные кадры Resolve запрашиваются по необходимости через отдельный provider и передаются в памяти без промежуточного FFV1. PNG декодируется на CPU; прямого доступа к GPU-буферу Resolve нет. Устранено повреждение последовательных PNG: самостоятельные изображения помечаются `AV_PKT_FLAG_KEY`.
- CUDA выполняет flow warp, consistency/confidence, сглаживание масок и смешивание перед интеграцией экспозиции. Farneback остаётся на CPU на уменьшенном изображении, как в проверенном Comfy-референсе. Кэши кадров/пар адаптируются к доступной VRAM; рабочие буферы экспозиции учитываются отдельно от бюджета кэша.
- Исправлено зависание при переключении своего пресета после Factory Reset. Очистка кэша защищает используемые результаты и активный provider. Флаги предупреждений C++ ограничены CXX и не передаются NVCC.
- Добавлены регрессии CPU/CUDA flow, временного отображения входа, транспорта и точности пикселей PNG, защиты кэша и последовательной очереди/импорта/отмены.

## Что подтверждено

Пользователь подтвердил переключение пресетов, одинаковую длительность Raw/Processed, использование отключённой верхней дорожки и сохранность используемых клипов при очистке кэша.

Пользователь сообщил об успешной сборке и тестах CUDA sampler. Независимое сравнение с фактическим Comfy CUDA/OpenCV 4.11.0 дало для 12 сценариев максимум `max_error=1.69873e-05`, `mean_error=1.92856e-07` при допусках `1e-3/1e-5`. Это сравнение sampler на тестовых кадрах, а не доказательство полной идентичности Camera/Resolve.

После исправления PNG key packets пользователь подтвердил корректное изображение в прямом обработанном входе. Отдельный новый полный лог CTest не предоставлен.

## Что осталось проверить

**Новая групповая очередь ещё не имеет подтверждённого пользовательского PASS.** Сборки, тесты, проверки синтаксиса и Resolve при оформлении агент не запускал. Реальное ускорение в цифрах и поведение при сильном давлении на VRAM не измерены. Произвольный нелинейный speed ramp в Raw и семантика SourceEndFrame требуют отдельной проверки. Windows/macOS не проверены.

Команды выполняет пользователь:

```bash
cd /home/alex/Projects/ALEXZ_SilentFilm_OFX
cmake --build build-cuda --parallel 2 &&
ctest --test-dir build-cuda --output-on-failure
```

Для отдельной проверки Python-очереди без сборки:

```bash
PYTHONDONTWRITEBYTECODE=1 /usr/bin/python3 tests/cadence_bridge_tests.py
```

В Resolve: 2–3 подрезанных клипа, включая разные участки одного файла; Raw/Processed, Replace/Add Above, отмена, отсутствие сдвига соседей и повторного импорта. До завершения очереди монтаж и обработки не менять.
